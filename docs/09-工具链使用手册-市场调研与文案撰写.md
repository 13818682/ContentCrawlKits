### 0.2 数据采集类 — 网络调研与信息获取

#### 0.2.1 firecrawl（MCP 工具）

**安装方式**：`C:\Users\weiwei\.claude.json` → `mcpServers.firecrawl`

**特点**：Firecrawl 是网页抓取和搜索 MCP 服务器，提供全网搜索、单页抓取、站点地图发现、异步深度调研 Agent 等能力。已配置 API Key（`FIRECRAWL_API_KEY`）。

**作用**：竞品内容扫描、政策文件检索、家长讨论话题发现、特定页面深度阅读。

**主要命令及示例**：

| 命令 | 用途 | 示例 |
|------|------|------|
| `firecrawl_search` | 搜索全网内容，返回标题/URL/摘要 | 见下方示例1 |
| `firecrawl_scrape` | 抓取单页面完整内容（支持Markdown/HTML/截图等格式） | 见下方示例2 |
| `firecrawl_agent` | 启动异步深度调研Agent，综合多源信息输出结构化报告 | 见下方示例3 |
| `firecrawl_agent_status` | 查询异步Agent任务状态和获取结果 | 见下方示例4 |

**示例1 — 基础搜索**：
```bash
mcp__firecrawl__firecrawl_search \
  query="深圳中考 D类 非深户 志愿填报 录取率 2026" \
  limit=5 \
  sources=["web"]
```
返回：搜索结果列表，含标题、URL、摘要描述。

**示例2 — 深度抓取**：
```bash
mcp__firecrawl__firecrawl_scrape \
  url="https://szeb.sz.gov.cn/szzkw/zcwj/content/post_12687204.html" \
  formats=["markdown"]
```
返回：该页面的完整 Markdown 格式内容。

**示例3 — 异步深度调研**：
```bash
mcp__firecrawl__firecrawl_agent \
  prompt="调研深圳中考D类非深户考生家长的痛点、信息获取渠道、付费意愿，以及目前市面上的D类内容供给情况。输出结构化报告。"
```
返回：`{ "id": "job_xxx" }` — 一个任务ID，需用示例4轮询结果。

**示例4 — 查询异步结果**：
```bash
mcp__firecrawl__firecrawl_agent_status id="job_xxx"
```
当返回 `status: "completed"` 时，`data` 字段包含完整的调研报告。

**使用建议**：
- 简单关键词搜索 → `firecrawl_search`，秒级返回
- 精读具体页面 → `firecrawl_scrape`
- 复杂综合性调研（需跨多个来源分析）→ `firecrawl_agent`，需等待几分钟
- 同一会话中不重复抓取相同URL（遵守 CLAUDE.md 规则1）

### 0.3 文档处理类 — 本地文件与文档管理

#### 0.3.1 mcp-docs（MCP 工具）

**安装方式**：`C:\Users\weiwei\.claude.json` → `mcpServers.mcp-docs`

**特点**：面向 Markdown 文档的专业编辑器，支持创建、编辑、搜索、导航生成、健康检查等操作。

**作用**：`docs/` 目录下所有结构化文档的创建和维护。不要用于简单文件读取（应使用 fs）。

**主要命令及示例**：

| 命令 | 用途 | 示例 |
|------|------|------|
| `write_document` | 创建/覆写 Markdown 文档 | `write_document path="09-手册.md" content="..."` |
| `read_document` | 读取文档内容 | `read_document path="docs/01-PRD-...md"` |
| `edit_document` | 行级精确编辑 | 见下方示例 |
| `search_documents` | 搜索文档内容 | `search_documents query="指标生"` |
| `list_documents` | 列出目录下所有文档 | `list_documents path="docs/"` |
| `validate_documentation_links` | 检查文档内部链接有效性 | — |
| `generate_documentation_navigation` | 自动生成文档导航结构 | — |

**示例 — 行级编辑**：
```bash
mcp__mcp-docs__edit_document \
  path="01-PRD-深圳中考志愿填报AI自动化内容平台.md" \
  edits=[{"oldText":"待定","newText":"已确认：MediaCrawler为采集层首选"}]
```

> ⚠️ **注意**：`write_document` 的 `path` 参数不要加 `docs/` 前缀，否则会写入 `docs/docs/` 嵌套路径。

**安装方式**：`C:\Users\weiwei\.claude.json` → `mcpServers.doc-convert`

```bash
  file_path="E:/1.HSEE/1.HSEE-Prj/3.政策文件资料/2026深圳中考招生工作通知.pdf"
```
返回：PDF 的完整 Markdown 文本（含表格保留）。

**示例2 — 转换 Word 文档**：
```bash
mcp__doc-convert__convert_to_markdown \
  file_path="E:/1.HSEE/1.HSEE-Prj/4.数据导入模板/学校介绍模板.docx"
```
返回：DOCX 的 Markdown 格式内容。

**示例3 — OCR 识别图片中的文字**：
```bash
mcp__doc-convert__convert_to_markdown \
  file_path="E:/1.HSEE/1.HSEE-Prj/5.截图素材/分数线表格截图.png"
```
返回：图片中 OCR 识别出的文本。

**使用建议**：
- 文件夹批量整理前，先用 `convert_to_markdown` 统一格式
- PDF 政策文件 → 转 Markdown → 用 `mcp-docs` 存入 docs/ 目录
- 图片中的表格数据 → OCR 转文字 → 手动校验关键数字

### 0.4 分析洞察类 — 用户洞察与竞品研判

#### 0.4.1 insight（Superpowers 技能）✅ 已安装

**安装路径**：`C:\Users\weiwei\.claude\skills\insight\`

**来源**：`superpowers@claude-plugins-official`（v6.2.0）

**特点**：用户需求洞察与产品机会分析技能。基于四段式框架（用户画像→情绪动因→产品机会→小而美创业落地），10分钟产出传统方法需数周的结构化洞察。

**作用**：新产品/服务开发前的用户分析、品类切入前的市场机会评估、营销策划中的用户动机挖掘、差异化定位。

**触发方式**：直接对话，或通过 `Skill` 工具调用 `insight`。

**四段式框架**：

| 阶段 | 核心问题 | 输出物 |
|------|---------|--------|
| 阶段一：用户画像识别 | 谁是目标用户？避开"抓住所有人"陷阱 | 4类用户画像 + 核心用户判断 |
| 阶段二：情绪动因分析 | 用户真正的痛点/痒点/爽点是什么？ | 可直接用于文案的情绪表达 |
| 阶段三：产品机会转化 | 情绪洞察如何转化为可落地的需求？ | P0/P1/P2级机会清单 |
| 阶段四：小而美创业落地 | 怎么启动？怎么获客？怎么盈利？ | 90天可执行行动计划（可选） |

**示例**：
```
用 insight 技能分析深圳中考D类（非深户）考生家长，
产品是HSEE小程序提供的深圳中考志愿填报咨询服务和付费学校深度报告，
需要全流程分析（含用户画像+情绪洞察+产品机会）
```

**使用建议**：
- 首次切入新用户群（如D类家长、低分段家长、指标生家长）→ 必须跑一遍 insight
- 已有用户画像但需要更深挖情绪动机 → 只跑阶段二
- 需要把洞察转化为具体内容选题 → 跑阶段一至三
- 一人公司/小团队做新产品决策 → 加跑阶段四

##### 0.5.2.1 generate_brief — 生成写作简报

**作用**：在开始写文章、撰稿之前，生成一份正式的写作简报（brief），确认选题方向、目标读者、风格、模式后再动笔。

## 五、最佳实践与注意事项

### 5.1 调研阶段

1. **先用 insight 定方向，再用 firecrawl 做验证**：insight 输出的用户画像和情绪洞察提供"假设"，firecrawl 搜索结果用来"验证假设"——你的目标用户真的在搜这些关键词吗？
2. **firecrawl_agent 适合复杂调研，但需要等待**：提交后记录 job ID，用 `firecrawl_agent_status` 轮询结果。简单的关键词搜索用 `firecrawl_search` 即可。
3. **竞品分析要"交叉验证"**：不要只跑一个工具。`market-competitors` 看定位策略，`competitor-profiling` 看内容细节，`customer-research` 看真实用户评价。
4. **及时存档到 claude-mem**：调研结论通过 `claude-mem` 写入长期记忆，后续会话自动加载，避免重复调研。

### 5.2 文案阶段

1. **品牌调性是"1"，分平台变形是"N"**：先跑 `market-brand` 统一调性，再在各平台变形。否则9个平台听起来像9个人写的。
2. **生成→校验→修改闭环**：`better-writer` 生成初稿 → `validate_style` 校验 → 人工精修数据准确性 → 再校验 → 发布。
3. **平台规则先行**：动笔前 `get_platform_rules` 查规则，写完后 `validate_style` 查违规。两步兜底。
4. **08说明书是基础参考，新工具是提效引擎**：`docs/08-九大平台文案撰写要求说明书.md` 中的AI提示词模板和各平台要求仍然有效，新工具（content-production、better-writer）的作用是批量生成初稿和自动化变形，不是替代。
5. **合规检查是最后一道门**：任何工具生成的文案，发布前必须对照 `docs/04-内容发布合规检查清单.md` 逐项核对。AI生成的内容不保证合规。
6. **"一鱼多吃"工作流最省力**：公众号深度长文（`better-writer`）→ 小红书图文（`social`变体）→ 抖音脚本（`social`变体）→ 知乎问答（`social`变体），一条母版产出5-8条子内容。

### 5.3 工具边界

| 不要用 | 原因 |
|--------|------|
| `insight` 替代 real user interview | insight 提供方向感，不替代真实用户调研 |
| `firecrawl` 直接搬运竞品内容 | 语义相似度必须<30%（合规红线） |
| `better-writer` 不经人工审核直接发布 | AI生成内容需人工复核数据准确性 |
| `market-copy` 不经人工审核直接发布 | AI生成内容需人工复核数据准确性 |
| 跳过 `market-brand` 直接写文案 | 缺乏统一调性，9个平台声音不一致 |
| 跳过 `validate_style` 直接发布 | 可能存在禁用词/标点/格式违规 |
