# 自媒体导流小程序与全流程数据监控方案

> **一句话**：自媒体矩阵负责「信任 + 流量」，小程序负责「承接 + 转化」，路径参数负责「归因」，数据监控负责「反馈闭环」。本方案把这三件事串成一条可执行的全流程。

## 一、整体链路：内容 → 导流 → 承接 → 转化 → 监控

```
┌─────────── 自媒体内容层（9平台）───────────┐   ┌────────── 小程序承接层 ──────────┐
│ 公众号/小红书/抖音/头条/知乎/微博/快手/B站/贴吧 │   │ 文章/QA/学校库/志愿方案/测评     │
│     建立信任 + 汇聚流量                       │   │     承接 + 转化（注册/付费）      │
└──────────────┬────────────────────────────┘   └───────────────▲──────────────────┘
               │ ① 合规导流入口（见二）                          │
               ▼                                                │
      每个入口都带  ?from=来源标记  ─────────────────────────────┘
               │                                                │
               ▼                                                ▼
┌─────────── 数据监控层（四段漏斗，见三）────────────────────────┘
│  内容数据 → 引流数据 → 小程序数据 → 转化付费数据               │
│  每段各自指标 + 相邻段转化率 → 北极星指标                      │
└──────────────────────────────────────────────────────────────────┘
```

**三条铁律**：
1. **每个入口必带 `?from=`**——没有归因的流量 = 白做（见四）。
2. **导流必须合规**——知乎不贴外链（17号规则）、小红书主页简介承接、抖音主页简介承接（见二）。
3. **数据每周归档**——每周对比同口径，纳入 `docs/15-运营数据/` 周报（已有惯例）。

## 二、各平台导流到小程序：合规方式 + 承接物

### 2.1 导流合规边界（先定死）

| 平台 | 可否贴小程序码/链接 | 合规导流方式 |
|---|---|---|
| **公众号** | ✅ 可（图文内嵌小程序卡片、菜单栏、阅读原文） | **最强导流位**：图文底部小程序卡片 + 菜单栏挂小程序 |
| **视频号** | ✅ 可（视频挂小程序链接、直播间挂载） | 视频页挂小程序、公众号互跳 |
| **抖音** | ⚠️ 主页可挂（抖音小程序/官网链接，需资质） | 主页简介写「同名微信小程序」；评论区置顶引导搜索 |
| **小红书** | ❌ 正文不能贴码/链接 | **主页简介**放「同名小程序/公众号」；评论置顶引导 |
| **今日头条** | ⚠️ 文末可放链接（需企业号资质） | 文末「同名搜索」；主页简介 |
| **知乎** | ❌ 回答/想法不能贴外链（17号红线） | **主页简介**写「公众号同名」→ 公众号 → 小程序（间接） |
| **微博** | ⚠️ 可放链接 | 微博主页简介 + 置顶微博引导 |
| **快手** | ⚠️ 主页可挂 | 主页简介 |
| **B站** | ⚠️ 简介/评论区可放 | 简介 + 置顶评论（暂不重点，见运营路线图） |

> **核心规律**：微信生态内（公众号/视频号）= 直接导小程序；生态外（小红书/知乎/抖音）= 先导**主页简介** → 主页简介写小程序/公众号名 → 用户搜索进入。**没有平台能一键从自媒体直达小程序**，微信生态外的链路是「自媒体 → 主页简介 → 微信搜索 → 小程序」。

### 2.2 小程序承接物（导流进去后让用户留下）

用户从小程序进入后，需要有**即时价值的承接页**（不是直接弹付费）：

| 承接物 | 页面 | 作用 | 转化钩子 |
|---|---|---|---|
| **文章落地页** | `/pages/articles/detail?id=X` | 承接内容阅读（已在实现） | 文末关联「志愿方案」引导 |
| **免费测评** | `/pages/quizzes`（测评） | 即时满足：「一次免费成绩匹配」 | 结果页 → 引导注册/付费解锁详细 |
| **学校库/查录取线** | `/pages/school-search` | 免费查数据（引流核心） | 查完 → 引导收藏/订阅 |
| **问答专区** | `/pages/qa` | 承接问答内容 | 相关问答 → 引导关注 |
| **志愿方案（付费）** | `/pages/plan` | 核心付费转化 | 测评/查分 → 方案生成 |
| **邀请裂变** | `/pages/invite` | 老带新 | 邀请奖励（已在实现） |

**承接页铁律**：外部来的用户（带 `?from=`）进首页后，**首页优先展示信任证据**（数据来源标注、权威背书），而非从头科普——对齐 10 号文档「多路径模型：外部流量信任用户需要快速确认信号」。

## 三、全流程数据监控：四段漏斗指标体系

### 3.1 四段漏斗总览

| 段 | 范围 | 关键指标 | 采集方式 |
|---|---|---|---|
| **A. 内容段** | 内容发布 → 曝光/互动 | 曝光量、阅读/播放、点赞/收藏/评论/分享、完播率 | 各平台后台 + 蚁小二汇总（已有周报惯例） |
| **B. 引流段** | 内容 → 点击导流入口 | 主页访问率、小程序点击/扫码数、搜索进入数 | `?from=` 参数统计 + 小程序流量来源 |
| **C. 小程序段** | 进入 → 注册/活跃 | 新用户注册数、注册转化率、7日留存、页面停留 | 小程序后台（微信分析）+ 自建事件埋点 |
| **D. 付费段** | 注册 → 付费/续费 | 付费转化率、客单价、LTV、续费率 | 小程序后台 + 数据库订单表 |

### 3.2 各段核心指标 + 相邻段转化率

**北极星指标**（承运营路线图基线）：
- **内容质量**：抖音完播率（首周基线 6%）
- **获客引擎**：小红书获粉转化率（首周基线 42粉/2746观看）
- **→ 新增强化：小程序注册转化率**（引流→注册，这是「自媒体→小程序」是否跑通的关键）

**相邻段转化率**（每段之间的"漏勺"检查点）：

```
A→B 内容互动率 = 互动数 / 曝光          （内容是否吸引点击导流入口）
B→C 引流转化率 = 小程序进入 / 主页访问  （导流入口是否有效）
C→D 付费转化率 = 付费用户 / 注册用户    （小程序承接是否促成付费）
```

### 3.3 数据采集与归因表（落地）

| 指标 | 来源 | 落地方式 |
|---|---|---|
| 内容曝光/互动 | 平台后台 + 蚁小二 | 每周导出，纳入周报 |
| 主页访问 | 各平台创作者中心 | 周报记录 |
| **小程序进入来源** | 微信小程序后台「流量分析」 | **按来源渠道**（公众号/搜索/分享/扫码）看分布 |
| **注册归因** | 小程序后端 | **`?from=` 参数落地 → 注册时记录来源字段**（见四） |
| 付费 | 小程序后台 + 数据库 | 订单表关联注册来源 → 算各渠道 LTV |

## 四、路径参数追踪：`?from=` 归因方案

> 记忆基线已有：`?from=xhs_account1_20240801`（validation-phase-plan）。这里固化为标准。

### 4.1 参数规范

```
?from={平台}_{账号}_{日期}
示例：?from=ggzh_zhuli_20260901   （公众号·主力号·9月1日）
      ?from=xhs_a_20260901        （小红书·A号）
      ?from=douyin_b_20260901     （抖音·B号）
```

- **平台缩写**：`ggzh`公众号 / `xhs`小红书 / `douyin`抖音 / `tt`头条 / `zhihu`知乎 / `shipinhao`视频号 / `wb`微博 / `ks`快手 / `bili`B站
- **日期** = 内容发布时间（区分同一账号不同批次）
- **通用来源**：`?from=search`（搜索进入）/ `?from=share`（微信分享）/ `?from=scan`（扫码）

### 4.2 落地改造（小程序端 + 后端 —— 🔧 归 1.HSEE-Prj 执行）

> 以下为开发实现要点，交 1.HSEE-Prj 按 5.4 需求单执行；本仓只出规格、不碰代码。

1. **小程序侧**：所有导流落地页（article/qa/school-search 等）读取 `options.from`，存入 `app.globalData` 或缓存 → 注册时带上。
   - 现状：`onShareAppMessage` 已带 `path` → 追加 `?from=share` 即可。
   - 公众号图文卡片：`<mp-miniprogram>` 组件的 path 可传 `?from=ggzh_xxx_日期`。
2. **后端侧**：注册接口接收 `from` 字段，写入 `users.source` 列（或 `user_sources` 表）。已有 `invite_system` 迁移（009），可复用其来源记录机制。
3. **查询**：按 `source` 分组统计 → 算出各渠道 B→C→D 转化率。

### 4.3 归因分析（每周）

| 分析 | 动作 |
|---|---|
| 哪个渠道进小程序最多？ | 按 `from` 前缀聚合小程序注册数 |
| 哪个渠道注册转化最高？ | B→C 转化率排序 |
| 哪个渠道付费用户最多？ | C→D 转化率 + LTV |
| 内容优化依据 | 高转化选题 → 加权生产（对齐 P1-03 数据反馈闭环） |

| 事项 | 归属 | 说明 |

| 注册接口新增 from 字段 | 🔧 1.HSEE-Prj | 后端 bff 注册接口 + 数据库 |
| 公众号图文小程序卡片 | 📋 本仓运营 | 公众号后台配置（卡片 path 带 from） |
| 各平台主页简介「同名小程序」话术 | 📋 本仓运营 | 内容侧配置，见 2.2/2.3 |

### 5.3 落地三步（按优先级，标注归属）

1. **第一步（开发·1.HSEE-Prj）**：`?from=` 参数接入小程序落地页 + 注册来源记录 → 本仓出**开发需求单**（见 5.4），由 1.HSEE-Prj 执行。
2. **第二步（运营·2周内，本仓可先行）**：公众号图文挂小程序卡片（带 from）+ 各平台主页简介统一「同名小程序」→ 先打通**微信生态内闭环**（公众号→小程序）。**这一步不依赖代码，本仓现在就能做。**
3. **第三步（1个月内）**：小程序侧 `from` 数据可用后，测试各渠道进入 → 建立四段漏斗周报模板。

### 5.4 开发需求单（交 1.HSEE-Prj，本仓出规格）

```
需求：自媒体导流来源追踪
1. 小程序落地页（article/qa/school-search 等）读取 options.from 并存入 globalData/缓存
2. 注册接口接收 from 参数，写入 users.source（复用 invite 来源机制）

验收：进入落地页带 ?from=ggzh_xxx_日期 → 注册后 users.source 有值 → 可按来源分组统计
```
