# 多城市扩张模式评估：账号矩阵策略

## 一、结论

中考志愿填报是**强地域性品类**（政策/总分/批次/学校/分数线逐城不同）。这决定了：

- **模式 B（单号覆盖全国）基本不成立**：省了运营成本，也基本省掉了营收。
- **模式 A（城市矩阵）方向正确**，但有手机号数量、平台风控、本地化成本三个硬约束。
- **最优解是分阶段 + 按平台地域性分层的混合策略**，而非二选一。

## 二、两种模式对比

| 维度 | 模式 A 城市矩阵（广州中考/东莞中考） | 模式 B 单号覆盖全国（中考服务） |
|------|------|------|
| 内容针对性 | 强（本地学校/分数线/政策） | 弱（通用内容） |
| 转化率 | 高 | 低 |
| 本地搜索命中 | 高（"广州中考"直接命中） | 低（"中考服务"泛词竞争惨烈） |
| 平台推荐权重 | 高（有地域锚点） | 低（无地域锚点） |
| 账号数量 | 9N（N 城市） | 9 |
| 手机号需求 | N 个 | 1 个 |
| 运营人力 | 高（养 N×9 号） | 低 |
| 封号风控风险 | 高（矩阵号判定） | 低 |
| 品牌统一 | 弱（分散） | 强 |
| 本地化内容成本 | 高（N 套数据） | 低（1 套通用） |

## 三、模式 B 失效的四个原因

1. **搜不到**：家长搜"XX 市中考"本地词，通用号不命中；泛词"中考服务"竞争激烈。
2. **推不动**：平台算法按地域分发，通用号无本地推荐权重。
3. **不信任**：家长要"懂我城市"的本地号。
4. **做不深**：通用内容无法深入任何城市的学校/分数线，放弃了你唯一的差异化壁垒（学校数据）。

## 四、模式 A 的三个硬约束

| 约束 | 说明 |
|------|------|
| 手机号/账号数量 | N×9 账号、N 手机号；工信部"一证五卡"（同身份证同运营商 5 张，三家 15 张），N>15 需多人身份证 |
| 平台风控 | 多账号同设备/同网络 = 矩阵号判定、批量封号；每号需持续养号，1 人约可运营 30 号 |
| 本地化成本 | 框架可复用，但每城学校/分数线/政策数据需替换，N 城 = N 套数据 |

## 五、推荐：三阶段 + 按平台分层

### 5.1 三阶段演进

| 阶段 | 策略 | 规模 |
|------|------|------|
| 验证期 | 模式 A 单城市（深圳）跑通闭环 | N=1，9 账号 |
| 复制期 | 模式 A 复制珠三角重点城市（广州/东莞/佛山） | N=2–3，27 账号 |
| 规模期 | 混合：主品牌号（全国）+ 重点城市号 + 小程序统一 | N=10+，分层 |

### 5.2 按平台地域性分层（关键省力原则）

- **城市号（模式 A）**：公众号、小红书、抖音——本地搜索权重高，值得做本地号。
- **统一号（模式 B）**：微博、贴吧、知乎——地域性弱，一个号覆盖即可。

> 分层后，规模期账号数从"9N"降到"约 4N + 4"（3 个高地域平台做城市号 + 其余平台统一号），账号数砍半以上。

## 六、产品侧多城市重构（✅ 已实施）

多城市支持的最大工作量在产品侧，**当前 `1.HSEE-Prj` 已完成 city 维度重构**，小程序支持多城市注册与当地城市志愿填报。技术方案要点：

1. 数据模型加 `city` 维度（学校/分数线/政策/名额分配表按城市组织）；
2. 决策模型参数化（不同城市总分、批次、录取规则不同）；
3. 内容库按城市组织（本地学校介绍、本地政策解读）；
4. 小程序注册/选城流程（用户进来选城市）。

## 七、行动建议（更新）

1. 现阶段只做**深圳单城市**（模式 A 的 N=1），跑通"内容→引流→小程序→订阅"全闭环。
2. 闭环验证后，复制到**东莞**，再扩展至**广州**（模式 A，N=3，仍在合规线内）。
3. 规模期再切换混合 + 分层策略（主品牌号 + 重点城市号 + 按平台分层）。
