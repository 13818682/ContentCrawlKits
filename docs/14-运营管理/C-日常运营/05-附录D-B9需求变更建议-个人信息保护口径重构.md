# 需求变更建议：B9 个人信息保护口径重构

> **提出方**：1.HSEE-Prj（小程序产品仓）—— 即 05-附录A 需求单中的「执行方」
> **接收方**：ContentCrawlKits（内容/运营仓）—— 即该需求单中的「提交方」
> **日期**：2026-09-13
> **性质**：**执行方 → 提交方**的反馈，方向与 05-附录A 相反
> **涉及**：05-附录A 需求单 · **B9【P0】个人信息保护：隐私保护指引 + 未成年人单独同意**
> **边界声明**：本仓**不修改运营仓任何文档正文**，仅提出建议与依据；是否采纳、如何改写由运营侧决定。文末列出本仓**不受本建议阻塞、可并行开工**的部分。

## 一、结论摘要（先看这节）

1. **B9 的合规重心建议整体调整**：从「**未成年人监护人同意大工程**」转为「**最小化采集 + 自动化决策影响评估**」。前者在现行法律下**大部分不适用**，后者是**躲不掉的硬义务**，而两者的工作量差了一个数量级。

2. **分界线是 14 周岁，不是 18 周岁。** 中考考生通常已满 14 周岁（法定入学 6 岁 + 9 年义务教育），因此《个人信息保护法》第 31 条的「**监护人同意 + 专门个人信息处理规则**」**一般不适用**；其个人信息也**不属于法定敏感个人信息**。

3. **⚠️ 现 05-附录C《隐私政策》§4.1 存在口径错误，建议优先修订**：该节把「已满十四周岁未成年人」的个人信息也定义为敏感个人信息，与第 28 条不符，会让本服务自愿承担不必要的高义务。

4. **⚠️ 但不能表述为「我们不收集隐私、没有获取个人信息」。** 去标识化后的信息**仍然是个人信息**（第 73 条），仍适用《个人信息保护法》。若在政策里写「未获取」，反而违反第 17 条「真实、准确、完整」的告知义务，**自己制造一个新的违法点**。建议改为「**最小化采集 + 不采集敏感个人信息**」的准确表述。

5. **新增一项原需求单未覆盖的硬义务**：本服务核心功能（模拟推算 + 生成志愿方案）构成第 73 条意义上的「**自动化决策**」，依第 55 条应当**事前进行个人信息保护影响评估（PIA）并保存记录至少三年**。此项**与是否脱敏、是否涉及未成年人无关**，由服务形态决定。

## 二、法律依据（原文摘录，便于核对）

> 来源：中国人大网 / 中央网络安全和信息化委员会办公室（www.cac.gov.cn）公布的《中华人民共和国个人信息保护法》全文，2021-08-20 通过，2021-11-01 施行。

**第四条**　个人信息是以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息，**不包括匿名化处理后的信息**。

**第六条**　处理个人信息应当具有明确、合理的目的，并应当与处理目的直接相关，采取对个人权益影响最小的方式。**收集个人信息，应当限于实现处理目的的最小范围，不得过度收集个人信息。**

**第十三条**　符合下列情形之一的，个人信息处理者方可处理个人信息：（一）取得个人的同意；（二）**为订立、履行个人作为一方当事人的合同所必需**……

**第十五条**　基于个人同意处理个人信息的，**个人有权撤回其同意。个人信息处理者应当提供便捷的撤回同意的方式。**

**第十七条**　个人信息处理者在处理个人信息前，应当以显著方式、清晰易懂的语言**真实、准确、完整**地向个人告知下列事项：（一）处理者的名称或者姓名和联系方式；（二）处理目的、处理方式，处理的个人信息种类、保存期限；（三）个人行使权利的方式和程序……

**第十九条**　除法律、行政法规另有规定外，个人信息的保存期限应当为实现处理目的所必要的**最短时间**。

**第二十四条**　个人信息处理者利用个人信息进行**自动化决策**，应当保证决策的**透明度和结果公平、公正**……通过自动化决策方式作出对个人权益有重大影响的决定，个人**有权要求个人信息处理者予以说明，并有权拒绝个人信息处理者仅通过自动化决策的方式作出决定**。

**第二十八条**　敏感个人信息是一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息，包括生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等信息，**以及不满十四周岁未成年人的个人信息**。

**第三十一条**　个人信息处理者处理**不满十四周岁**未成年人个人信息的，应当取得未成年人的父母或者其他监护人的同意。

　　　　　个人信息处理者处理**不满十四周岁**未成年人个人信息的，应当制定专门的个人信息处理规则。

**第四十五条**　个人有权向个人信息处理者**查阅、复制**其个人信息……
**第四十六条**　个人发现其个人信息不准确或者不完整的，有权请求个人信息处理者**更正、补充**。
**第四十七条**　有下列情形之一的，个人信息处理者应当**主动删除**个人信息；未删除的，个人有权请求删除：（一）处理目的已实现、无法实现或者为实现处理目的不再必要；**（三）个人撤回同意**……

**第五十一条**　……（三）采取相应的加密、**去标识化**等安全技术措施……

**第五十五条**　有下列情形之一的，个人信息处理者应当**事前进行个人信息保护影响评估，并对处理情况进行记录**：（一）处理敏感个人信息；**（二）利用个人信息进行自动化决策**；（三）委托处理个人信息、向其他个人信息处理者提供个人信息、公开个人信息；（四）向境外提供个人信息；（五）其他对个人权益有重大影响的个人信息处理活动。

**第五十六条**　个人信息保护影响评估应当包括下列内容：（一）个人信息的处理目的、处理方式等是否合法、正当、必要；（二）对个人权益的影响及安全风险；（三）所采取的保护措施是否合法、有效并与风险程度相适应。
　　　　　个人信息保护影响评估报告和处理情况记录应当**至少保存三年**。

**第七十三条**（用语含义）
　　（二）**自动化决策**，是指通过计算机程序自动分析、评估个人的行为习惯、兴趣爱好或者经济、健康、信用状况等，并进行决策的活动。
　　（三）**去标识化**，是指个人信息经过处理，使其在**不借助额外信息的情况下无法识别特定自然人**的过程。
　　（四）**匿名化**，是指个人信息经过处理**无法识别特定自然人且不能复原**的过程。

**补充**：《中华人民共和国未成年人保护法》第七十二条亦以「**不满十四周岁**」为征得监护人同意的门槛，与上述一致。

## 三、逐项变更对照

对照 05-附录A 需求单 **B9** 的五项实现要求：

| 原需求 | 变更建议 | 理由 |
|---|---|---|
| **1. MP 后台配置《用户隐私保护指引》** | **保留，且优先级不变（P0）** | **与未成年人无关**：手机号属微信平台强制声明的隐私接口，未声明将返回 `errno 112`；提审时若勾选「未采集隐私」或未声明隐私协议，**接口调用权限会被平台回收**（官方错误 `appid privacy api banned`）。本仓已实测确认：自有代码调用的微信隐私接口**只有手机号一项** |
| **2. 首次进入考生档案页弹出隐私授权；拒绝时降级** | **拆分**：<br>· 微信侧 → 降为「手机号」单点（耦合按钮）<br>· 考生信息 → 由 05-附录C 政策正文承担告知义务 | 填写考生档案**不调用任何微信隐私接口**，微信框架**不会**自动触发弹窗；原表述把它当成微信框架的一部分，机制上不成立 |
| **3. 未成年人单独同意 + 监护人同意留痕** | **降级为「填写者授权声明 + 留痕」** | 已满 14 周岁不触发第 31 条。但因 05-附录B §7.3 已写入监护人同意条款（协议既写即须履行），故保留一个**轻量勾选 + 后端留痕**，不再建设独立的未成年人同意流程 |
| **4. 查阅 / 更正 / 删除 / 撤回授权入口** | **保留，但可轻量实现** | 第 15/45/46/47 条是**普适义务**，**不因去标识化而免除**。第 15 条明确要求「提供**便捷的**撤回方式」。实现上可与账号注销流程共用入口 |
| **5. 采集范围最小必要；隐私政策逐项披露** | **升级为核心项** | 第 6 条（最小必要）+ 第 17 条（真实准确完整告知）。本仓拟按「去标识化」方向收敛采集范围（见第五节），需政策正文同步反映 |
| **（新增）自动化决策影响评估** | **新增为 P0** | 第 55 条：利用个人信息进行自动化决策 → **事前 PIA + 记录保存 3 年**。由服务形态决定，**不可避免** |

## 四、需要运营侧修订的具体章节

### 4.1　`05-附录C-隐私政策`（**修订量最大，建议优先**）

| 章节 | 现状 | 建议 |
|---|---|---|
| **§4.1** | 「本服务涉及**未满十四周岁未成年人**和已满十四周岁未成年人的个人信息……**未成年人的个人信息属于敏感个人信息**」 | ⚠️ **与第 28 条不符**。建议改为：**不满十四周岁**未成年人的个人信息属敏感个人信息；已满十四周岁的按一般个人信息处理、采取相应保护措施 |
| **§4.2 监护人同意** | 对全部未成年人一律要求监护人同意 | 限定为**不满十四周岁**（第 31 条）。已满十四周岁的，填写者作出「已取得考生及其监护人授权」的声明即可 |
| **§4.3 单独告知** | 表述为独立环节 | 保留，但明确其触发条件是「处理敏感个人信息」（第 29 条），而非所有未成年人信息 |

## 五、本仓拟同步推进的采集范围收敛（供运营侧核对政策口径）

依据第 6 条最小必要 + 第 73 条去标识化，本仓拟按下表调整 `student_profiles` 的采集：

| 字段 | 处理 | 说明 |
|---|---|---|
| `name` | **改为「称呼」**，界面明示「填『张某某』或昵称即可，无需真实全名」，且不作真实性校验 | 切断最主要的身份标识 |
| `junior_high_school` | **保留** | 决定指标生位次，是方案质量的核心；且属学校名、非身份标识 |
| `exam_scores` | **保留**，但收敛为**只需总分**，不要求各科明细 | 减少颗粒度即减少可识别性 |
| `academic_level` / `hukou_type` | 保留 | 决定分数线归属，系服务必需 |
| `housing_preference` / `target_schools` / `preferences` | 保留 | 本身即为意向信息，非隐私信息 |
| `grade_score` | **复核是否仍被使用**，冗余则删 | 最小必要 |

**请在政策正文中据实披露上述范围**，并明确列出不采集的项。

## 七、待运营侧确认的事项

1. **是否采纳本建议**的口径调整（第 28/31 条的 14 周岁分界）。
2. **不满十四周岁的情形如何处理**：本服务面向中考考生（通常已满 14 周岁），但个别考生可能偏小。本仓建议**不采集年龄**，改由政策正文声明「本服务面向中考考生（通常已满 14 周岁）；若为不满 14 周岁的考生填写信息，请务必在取得监护人同意后使用，并联系我们以适用专门的处理规则」。**请确认此口径是否可接受。**
3. **机构用户场景**（B9 之外）：教育咨询机构人员代家长录入考生信息时，我方系独立处理者还是受托人（第 21 条），性质不同则义务不同。本仓建议**在填写者声明中一并覆盖**（声明已取得该考生监护人授权），并在机构使用规模扩大后另立条款。**请确认是否需要现在就出机构条款。**
4. **PIA 的归属**：第 55 条的评估义务由个人信息处理者（我方）承担，但评估内容涉及运营口径。请确认 PIA 由本仓起草、运营侧会签。
