## 一、为什么要这份确认

| # | 理由 |
|---|---|
| **1** | **第 21 条的硬要求**：个人信息**委托处理**，须**约定**处理目的、期限、处理方式、保护措施及双方权利义务，并**对受托人的处理活动进行监督**。口头/默认状态不满足"约定" |

| **3** | **举证场景真实存在**：发生个人信息投诉、12315/消协问询或监管检查时，"我们已要求服务商……"必须有**可出示的证据** |
| **4** | **上线前必须落定**：《隐私政策》一旦发布，承诺即生效。**不得**带着"已承诺但无据"的状态上线 |

### ② ⚠️ 反向发现（原要函未覆盖，必须问）

《**DeepSeek 用户协议**》§4.3：

> 为向您提供连续、高质量的服务，**在经安全加密技术处理、严格去标识化且无法重新识别特定个人的前提下，我们可能会将服务所收集的输入及对应输出，用于模型训练和服务的优化。** 如您拒绝将您的数据用于模型训练，可以在产品内通过关闭"数据用于优化体验"来选择退出，关闭后您的输入和输出不会再用于我们的模型训练。

而《开放平台服务协议》开篇即声明：

> 《DeepSeek开放平台服务协议》**作为《DeepSeek用户协议》项下所指的具体协议及其组成部分**；《DeepSeek用户协议》、本协议以及其他相关协议、政策或指引，**以上共同组成了您在使用DeepSeek开放平台时应当遵守的约定和条款**。

**→ 歧义**：开放平台协议**未排除**《用户协议》§4.3。故 **§4.3 是否适用于 API 用户、以及在 API 场景下如何行使"退出"权**（API 侧不存在"数据用于优化体验"这个产品开关），**协议文本自身答不出来**。

> ⚠️ **这一条把本项的优先级从 P1 拉到了必须做**：我方 `05-附录C` 5.2（二）的对外承诺是"**要求其不得**用于模型训练"。**若 §4.3 适用于 API，则现行协议不仅没有禁止、反而保留了训练权**——此时问题就不只是"承诺无据"，而是 **对外表述可能与事实相反**。
> （外部检索到两种相反说法，均**未见官方书面澄清**，故不以任何一方为准，**以要函答复为准**。）

| **§5.5** | "**您的终端用户**…其被收集的个人信息的处理规则**不在该隐私政策的说明范围内**，**您作为该场景下个人信息处理**活动的**处理者**应当向终端用户披露…" | 明确**我方是处理者**、终端用户信息不在 DeepSeek 隐私政策内——支持我方对外披露口径 |

## 五、兜底与三种收口（★ 发布前必须落定）

> ⚠️ **2026-09-21 修订**：原兜底表述「我们**已通过服务协议要求其**不得将您的信息用于模型训练」**现已不成立**——经 §二·A 核查，《开放平台服务协议》**根本不含**"不得用于模型训练"的要求，写"已通过服务协议要求其"属**不实陈述**（比原问题更糟）。以下为修订后的三选一。

| | 情形 | `05-附录C` 5.2（二）应怎么写 | 是否可发布 |
|---|---|---|---|
| **甲·首选** | 09-23 前取得书面确认，且答复与现文一致 | 维持现文：要求其**不得**将…用于模型训练或任何其他目的（**并注明确认依据与日期**） | ✅ |
| **乙·答复口径不同** | 取得答复，但对方口径不等于"不得"（**尤其 §4.3 被判适用**） | **必须按对方实际口径据实改写**，不得沿用现文 | ✅（改后） |
| **丙·兜底（已修订）** | 截止日仍未取得答复 | **不得**写"要求其…"或"已通过协议要求其…"——两者都暗示对方已受约束。<br>改为**只陈述我方已做的动作**：<br>「我方**已要求**服务商不得将您的信息用于模型训练，并**已就此向其发出书面确认请求**（2026-09-__ 发出）」 | ⚠️ 可发但**须同步 PIA 标注为未闭合** |

**判定标准**：三种写法在举证责任上完全不同——
- "要求其不得…" = **主张**（需举证据）
- "已通过服务协议要求其不得…" = **声称已有协议依据**（本例**不实**）
- "已要求…并已发出书面确认请求" = **只陈述我方行为**（**唯一在无回执时也站得住的写法**）

- **恢复条件**：确认到手后**改回甲**，并回填 §四。
- **改完动作**：① 同步 `05-附录F` §11.4 状态；② 回写 `00-运营路线图-总览.md` 中 `05-附录C` 的版本行。
