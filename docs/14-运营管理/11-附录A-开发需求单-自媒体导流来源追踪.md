## 一、背景与目标

自媒体矩阵（公众号/小红书/抖音/知乎等）正在为 HSEE 小程序导流。目前无法判断**流量从哪个渠道来、注册/付费归因到哪个渠道**——没有归因，运营只能看总量、不能指导投放和内容优化。

**目标**：小程序能记录每个新用户的来源渠道，运营可按来源分组统计注册/付费转化率。

## 二、需求明细

### 1. 小程序落地页读取来源参数

- **涉及页面**：导流落地页（`/pages/articles/detail`、`/pages/qa`、`/pages/school-search` 等）。
- **实现**：页面 `onLoad(options)` 读取 `options.from`，存入 `app.globalData.from` 或本地缓存。
- **现状参考**：`pages/articles/detail.js` 的 `onShareAppMessage` 已返回 `path: '/pages/articles/detail?id=' + articleId`——只需 path 追加 `?from=share`。

### 2. 注册接口接收来源字段

- **位置**：后端注册接口（bff）。
- **实现**：接收 `from` 参数，写入 `users.source` 列（如无该列，建 `user_sources` 表；可复用既有 `invite_system` 迁移 009 的来源记录机制）。
- **传递链**：落地页 `options.from` → `app.globalData` → 注册请求体 `from` → 数据库。

### 3. 分享时带来源

- `onShareAppMessage` 的 `path` 追加 `?from=share`，让微信分享进来的用户也能归因到"分享"渠道。

### 4. 归因查询接口（供运营周报读取）

- 提供按 `source` 分组的统计接口：注册数、付费数（可选，配合订单表）。
- 供运营侧周报（`docs/15-运营数据/00-周运营数据分析报告模板-v2.md` 第五节）读取。

## 三、验收标准

- [ ] 带 `?from=ggzh_zhuli_20260901` 进入落地页 → 注册后 `users.source` = `ggzh_zhuli_20260901`
- [ ] 无 `from` 参数时默认 `unknown`（不报错）
- [ ] 分享链接自带 `?from=share`
- [ ] 可调用接口按 `source` 分组返回注册数
- [ ] 老用户不受影响（仅新注册记录来源）

## 四、来源参数规范（已定，勿改）

```
?from={平台}_{账号}_{日期}
示例：?from=ggzh_zhuli_20260901
平台缩写：ggzh公众号 / xhs小红书 / douyin抖音 / tt头条 / zhihu知乎 / shipinhao视频号 / wb微博 / ks快手 / biliB站
通用来源：?from=search（搜索）/ ?from=share（微信分享）/ ?from=scan（扫码）
```
