# 深圳中考志愿填报AI自动化内容平台 — 业务需求说明书 (PRD)

## 文档概述

本文档定义「深圳中考志愿填报垂直AI自动化内容平台」的业务需求，涵盖市场研判、用户分析、竞品对标、功能需求分级、量化指标及验收标准。所有技术方案设计（参见 `./tech-design.md`）均绑定本文档对应章节，实现业务-技术双向追溯。

---

## 1. 市场研判

### 1.1 赛道概况

| 维度 | 数据 |
|---|---|
| 深圳中考考生规模 | 2026年约13万+考生，逐年增长 |
| 目标家长群体 | 35-45岁初三家长，高度焦虑、决策参与深 |
| 内容需求周期 | 每年3-8月（政策期→填报期→录取期），约6个月高密度内容消费 |
| 核心痛点 | 政策复杂多变（630分新制、走读调剂、指标生规则）、信息碎片化、官方语言难懂 |
| 2026年关键变化 | 总分610→630（理化实验+20分）、体育考二变三、走读调剂选项、3+4中本贯通试点 |

**结论**: 深圳中考志愿填报是刚需高频垂直赛道，每年固定13万+家庭必须面对，信息不对称导致的焦虑催生强付费意愿。

### 1.2 竞品对标

#### 直接竞品

| 竞品 | 定位 | 核心功能 | 优势 | 劣势 |
|---|---|---|---|---|
| **中考志愿网 (zkzyw.net)** | 数据查询+AI填报工具 | 学校数据库、AI/DIY志愿填报、趋势统计、微信小程序 | 官方数据齐全、被人民日报报道、有微信生态 | 偏工具属性，内容运营弱；无自媒体矩阵引流 |
| **深校家长帮 (知乎/公众号)** | 内容型升学自媒体 | 政策深度解读、10大要点拆解、案例分享 | 内容专业度高、有固定粉丝群 | 单人运营，产能有限，无自动化；无数据工具 |
| **各本地升学大V** | 碎片化自媒体 | 小红书/抖音政策解读、志愿填报技巧 | 粉丝粘性高、内容接地气 | 零散、质量参差、数据时效性差 |

#### 间接竞品

| 竞品 | 影响 |
|---|---|
| 深圳教育局官网/招考网 | 政策一手来源，但语言官方难懂，家长难以直接消化 |
| 通用AI工具 (Kimi/豆包/ChatGPT) | 可直接生成内容，但无深圳本地数据，容易产出通用套话 |
| 各地升学SaaS (如高考志愿类) | 模式可参考但中考地域性极强，需完全本地化 |

#### 差异化定位

本平台的竞争壁垒 = **竞品爆款话术 + 官方权威数据 + AI自动化流水线**

- vs 工具类竞品（中考志愿网）：我们以**内容引流**为核心，覆盖用户更早期的"知晓-信任"阶段
- vs 内容类竞品（深校家长帮等）：我们以**AI自动化**实现日产50+条多平台内容，产能碾压单人运营
- vs 通用AI工具：我们以**深圳本地知识库RAG**保证内容精准度，杜绝通用套话

## 2. 用户分析

### 2.1 用户旅程增强模型

原始线性模型（知晓→注册→使用→结束）存在不足：**寻找信任锚点、使用体验、持续升级、分享传播**四个环节贯穿全程、互相交织。

修订为**"一主线四贯穿"模型**：

```
主线: 知晓 ──→ 注册并体验 ──→ 订阅付费 ──→ 升级付费 ──→ 确定结果
         │            │              │              │            │
         └────────────┴──────────────┴──────────────┴────────────┘
                       四贯穿层:
         ┌── 寻找信任锚点（全程持续验证）──┐
         ├── 使用体验反馈（每个触点积累）──┤
         ├── 持续升级动力（价值感知驱动）──┤
         └── 分享传播意愿（后期释放为主）──┘
```

#### 各阶段用户关注点与产品设计要点

| 阶段 | 用户关注点 | 痛点 | 产品设计要点（追溯技术模块） |
|---|---|---|---|
| **知晓** | 这个平台/账号可信吗？讲的东西对吗？ | 信息过载、不知信谁 | 内容矩阵覆盖多平台，官方政策引用+本地数据增强可信度 |
| **注册并体验** | 免费内容有没有用？要不要付费？ | 付费犹豫、怕浪费钱 | 分层内容策略：免费干货建立认知→付费深度服务转化 |
| **寻找信任锚点**（贯穿） | 数据准不准？案例真不真？有没有成功案例？ | 被虚假宣传欺骗过的经历 | 每一篇内容嵌入真实数据+实名案例；评论区收集正面反馈 |
| **订阅付费** | 付费内容比免费好在哪？值不值？ | 决策成本高 | 明确免费vs付费边界，付费内容提供独家数据/个性化方案 |
| **继续体验** | 服务是否持续更新？数据是否最新的？ | 担心信息过时 | 自动同步最新政策数据、每日更新内容 |
| **升级付费** | 有没有更高阶的服务？一对一咨询？ | 个性化需求 | 分层产品线：内容→课程→咨询 |
| **确定结果** | 录取结果如何？和预期对比？ | 结果焦虑 | 提供录取后衔接内容（高一规划），延续关系 |
| **分享传播**（后期释放） | 分享有什么好处？会不会暴露隐私？ | 保护心理 | 匿名化案例分享、考试结束后引导分享给低年级家长 |

### 2.2 家长分享心理分析

| 维度 | 结论 | 内容策略影响 |
|---|---|---|
| 主动分享意愿 | **低** — 中考是竞争性事件，家长天然有信息保密倾向 | 不强推"转发有奖"机制，改用"收藏"+"评论区交流"鼓励互动 |
| 分享对象 | 仅限于亲人、同班家长小群，不会公开朋友圈转发 | 设计"小群分享卡片"（微信私密转发友好格式） |
| 分享时机 | **考试结束后**才愿意分享给低年级家长 | 后期（7-8月）集中投放"复盘经验"类内容，引导分享 |
| 替代传播方式 | 评论区留言、点赞收藏 是家长更舒适的互动方式 | 内容结尾设计引导评论区互动的钩子，而非直接要求转发 |
| 匿名化需求 | 讨论"别人家孩子的案例"远比自己分享安全 | 内容全部使用匿名化处理后的真实案例模板 |

## 3. 功能需求分级

| 编号 | 功能 | 说明 | 绑定PRD章节 |
|---|---|---|---|
| P0-01 | 多平台素材采集 | MediaCrawler集成，支持小红书/抖音/B站/知乎/公众号关键词+博主采集 | §1.1 赛道需求 |
| P0-02 | 语义去重与聚类 | tao-8k向量模型，相似度>0.7自动去重，K-Means自动分类 | §1.1 信息碎片化痛点 |
| P0-03 | 三级标签自动分类 | 一期标签（前/中/后期）×二期标签（23个业务主题）×三期标签（平台+形式） | §4 内容体系 |

| P0-05 | 深圳本地RAG知识库 | 存储历年分数线、高中梯队、指标生分配、政策原文，AI生成时自动检索 | §1.2 差异化定位 |
| P0-06 | 人工编辑工作台 | 70%AI骨架+30%人工润色，支持数据校验、案例插入、排版调整 | §2.1 信任锚点 |
| P0-07 | AI生成内容标识 | 按《人工智能生成合成内容标识办法》(2025/9/1生效)添加显式+隐式标识 | §5 合规要求 |

## 4. 内容体系（三级标签全量）

### 一级标签（时间周期）

- **A 前期政策筹备期** (3-5月)
- **B 中期填报实操黄金期** (6-7月)
- **C 后期录取收尾复盘期** (7-8月)

### 二级标签（业务主题，共23个）

**A组 (7个)**: A01基础政策解读、A02计分方式&科目规则、A03指标生政策、A04自主招生/特色招生、A05公/民办区别、A06报名流程资格审核、A07跨区报考限制

**B组 (9个)**: B01一分一段表、B02志愿批次规则、B03冲稳保梯度、B04指标生到校分配、B05填报避坑、B06公办高中梯队、B07民办筛选避雷、B08填报系统操作、B09特长生艺体

**C组 (7个)**: C01录取分数线复盘、C02滑档补救、C03补录全流程、C04中职择校、C05复读政策、C06高一衔接规划、C07年度案例复盘

### 三级标签（平台×形式）

平台: XHS/小红书、DY/抖音、SPH/视频号、GGZH/公众号、TT/头条、B/B站
形式: case/案例、qa/问答、table/数据表格、tip/避坑干货、policy/政策解读、template/模板方案

**示例标签**: `B03-XHS-tip` (中期冲稳保梯度-小红书图文-极简避坑干货)

## 5. 合规要求

| 编号 | 合规项 | 具体要求 | 法规依据 |
|---|---|---|---|
| C-01 | AI内容显式标识 | 文本起始/末尾添加"AI辅助生成"文字提示；音频/视频添加语音或界面提示 | 《人工智能生成合成内容标识办法》第4条 |
| C-02 | AI内容隐式标识 | 文件元数据中嵌入生成合成内容属性、服务提供者编码、内容编号 | 《标识办法》第5条 |
| C-03 | 传播平台标识 | 发布平台核验隐式标识，在内容周边添加"AI生成"提示 | 《标识办法》第6条 |
| C-04 | 标识不可删除 | 不得恶意删除、篡改、伪造、隐匿标识 | 《标识办法》第10条 |
| C-05 | 采集免责 | 抓取内容仅用于选题调研与行文参考，不得直接搬运商用 | 《著作权法》+ 行业实践 |
| C-06 | 语义相似度 | 发布前检测与全网现有文案相似度>30%强制重新改写 | 自定风控标准 |
| C-07 | 内容红线 | 不预测录取结果、不售卖内部名额、不违规承诺升学保障、不造谣政策 | 《广告法》+ 教育行业自律 |
| C-08 | 操作日志留存 | 爬虫采集记录、AI改写记录、人工编辑记录存档≥6个月 | 《标识办法》第9条（类比） |

**关键时间节点**: 《人工智能生成合成内容标识办法》于**2025年9月1日**起正式施行，所有AI生成内容发布必须合规。

## 6. 量化指标

| 指标 | 目标值 | 测量方式 | 达成时间 |
|---|---|---|---|
| 日内容产出 | 图文8-12篇 + 短视频4-6条 | 系统产出统计 | MVP上线后1个月 |
| 采集→发布全链路耗时 | 单条<2小时（热点模式） | 系统耗时日志 | V1.1 |
| 语义去重准确率 | >90%（人工抽检） | 周度抽检100条 | MVP |
| AI内容原创度 | 与源素材相似度<30% | 语义检测工具 | MVP |
| 单账号月均涨粉 | >500（自然流量） | 平台数据回传 | 运营3个月 |
| 内容覆盖平台数 | 6平台（小红书/抖音/视频号/公众号/头条/B站） | 分发日志 | V1.1 |
| 系统可用性 | >99.5%（月度） | 监控告警 | 生产环境 |
| 合规检测通过率 | 100% | CI/CD卡点 | MVP |

## 7. 验收标准

| 验收项 | 验收条件 | 验收方法 |
|---|---|---|
| 采集模块 | 能批量抓取小红书/抖音/B站关键词搜索结果，输出结构化JSON/CSV | 执行关键词"深圳中考志愿填报"采集任务，验证输出≥50条有效数据 |
| 去重聚类 | 100条相似素材输入，输出去重后≤40条，分类准确率≥90% | 人工标注100条素材，与系统输出对比 |
| AI生成 | 输入选题标签，输出符合对应平台模板的完整文案（含标题、正文、标签） | 对5个平台各测试10个选题，人工审核质量 |
| RAG检索 | 生成文案中引用的深圳中考数据与知识库一致 | 随机抽取20篇生成内容，逐条核验数据准确性 |
| 合规标识 | 所有AI生成内容包含显式标识+隐式元数据 | 自动化检测脚本 |
| 人工编辑 | 编辑可修改标题、正文、标签、嵌入数据表格 | 操作流程测试 |
| 分发（V1.1） | 一次操作，内容同步发布至≥3个平台 | 实测分发全流程 |

## 8. 项目风险

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| 平台反爬升级导致采集失败 | 高 | 严重 | 采集间隔≥12s、多账号轮换、备用商用工具(熊猫工坊) |
| AI生成内容被平台识别限流 | 高 | 中等 | 70/30人机协作、语义相似度<30%、合规标识反而降低风险 |
| LLM API成本超预期 | 中 | 中等 | 按量计费、缓存重复请求、本地小模型兜底 |
| 深圳中考政策重大变更导致知识库过期 | 中 | 严重 | 月度更新知识库、热点API自动监控、人工复核机制 |
| 版权纠纷（被竞品投诉爬取） | 低 | 严重 | 操作日志完整留存、AI深度改写、仅参考不搬运 |
| AI合规标识法规更新 | 中 | 中等 | 关注网信办动态、预留标识配置灵活调整能力 |
| 单点工具依赖风险(如某三方API停服) | 低 | 中等 | 每类工具保留备选方案（如MediaCrawler备选熊猫工坊） |
