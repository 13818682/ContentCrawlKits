### 0.2 六道工序（生产侧，逐单元登记）

`① 写作简报 → ② 初稿 → ③ 数据核验 → ④ 润色终稿 → ⑤ 合规检查 → ⑥ 素材齐套`

### 0.3 四条铁律

1. **计划与实际分列**——计划值写 `⏰拟…`，发布后改 `✅…+时刻`。**禁止用计划值冒充实际值**（P1-4 的 S1–S3 至今仍是计划值，无法判断是否真按点发出）。
2. **表格连成一张**——说明、版本升级、口径修订、例外，一律写进 **§六 变更与例外日志**，**不得插进表格行间**。
3. **发布时刻精确到分，并标注「定时 / 实时」**（例：`✅09-13 20:20 定时`）。
4. **发布后强制回填**——每条发布后 **+3 天**与 **+7 天**各回填一次 §五，口径与 `docs/15-运营数据/{城市}/` 周报一致（见 §5.1 口径映射表）。
5. **发布动作发布即报**（2026-09-15 新增，用户定）——**用户每次点完发布，主动告知「平台 + 单元 + 日期时刻 + 定时/实时」**，登记表当场把 `⏰拟…` 改成 `✅…时刻`。**不靠事后从平台导出反推**：导出只能覆盖有逐篇导出的平台（头条图文/小视频、抖音），公众号、小红书、以及分页截断的导出都核不全，反推会留下长期悬空的 ⏰。P1-4 的 S1–S3 就是拖到 09-15 才部分补回的实例。
