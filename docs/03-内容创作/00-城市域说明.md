## 二、五条作业规程

### 规程 1｜城市不进文件名，目录承载城市

```
✅ 正确：SZ深圳/P1-政策解码器/P1-5-名额分配指标生/…/P1-5-S1-深圳中考名额分配控制线：…-公众号-发布稿.md
✅ 正确：DG东莞/P1-政策解码器/P1-5-…/…/P1-5-S1-东莞中考名额分配控制线：…-公众号-发布稿.md
❌ 错误：DG东莞/…/P1-5-S1-深圳中考名额分配控制线：…-公众号-发布稿.md   ← 复制深圳稿忘了改
```

**标题里的城市名是内容**（「深圳中考…」讲的就是深圳），**不是标识**——它该随稿子一起改。目录才是标识。

### 规程 2｜🔴 禁止整树复制派生新城市

深圳树里带「深圳」的有：**411 个文件名**、**145 个脚本的图上文案**、**76 个脚本的绝对输出路径**。整树复制出来的城市树会满身是深圳，且**误跑脚本会写回深圳目录、覆盖已发布的配图**。

**正确做法**：新城市**重新生成**——目录骨架重建、文案按城市重写、脚本单独派生。

### 规程 3｜脚本不得硬编码绝对路径

现状：147 个 `_build_*.py` 中 **76 个**写着
`BASE = "E:/1.HSEE/6.ContentCrawlKits/docs/03-…/深圳…/"`。

**任何脚本跨城派生之前，必须先把 `BASE` 改为 `__file__` 相对定位**：

```python
BASE = os.path.join(os.path.dirname(os.path.abspath(__file__)), "…")
```

**改的时候必须断言**：新表达式解析出的绝对路径要与原字符串**逐字符相等**。因为 `BASE` 指向的目录**未必**是脚本所在目录（有脚本坐在 `子任务S1/` 里却往 `01.公众号/` 写），盲目替换会把产物写到错误位置。

### 规程 4｜路径深度自律（**非硬约束，先纠正一个误报**）

> ⚠️ **2026-09-19 更正**：本文件初稿曾写「本仓已有 116 个文件超限（最长 345）」。**该数字是错的**——当时用 `awk length()` / `wc -c` 计数，数的是**字节**，而中文在 UTF-8 中 1 字 = 3 字节。按 Windows MAX_PATH 实际使用的**字符**重算：

| | 误报（字节） | 实际（字符） |
|---|---|---|
| 最长路径 | 345 | **165** |
| ≥260 超限文件数 | 116 | **0** |

**当前没有任何文件超限**，最长 165 字符，距 260 尚有约 95 字符余量。**所以本条不是待修问题，只是编写习惯建议。**

建议改掉的是这种**浪费**写法——**完整中文标题在目录名和文件名里各写一遍**：

```
❌ 问答专区/005+2027年深圳中考会新增多少学位？中考压力会明显减轻吗？/01.公众号/0.旧版-配图v1（已废弃）/005+2027年深圳中考会新增多少学位？中考压力会明显减轻吗？-公众号-长图-极简版.png
```

**新增内容建议**：
- 目录名用**短标识**（`005-新增学位`），标题完整写在**文件名**里，不两处重复
- 废弃版本用后缀标记（`-旧版`），不为它单独建目录
- **历史文件不动**（已发布，改名有断链风险），只对新增生效

## 三、新城市开工顺序

派出新城市时按此顺序，**前一步不完成不进下一步**：

1. **数据源到位**——该城官方报考依据（手册/招考办文件）+ 分数线/招生计划
2. **城市清单填实**（`00-{码}{城市}-城市清单.md` 的「待确认」项全部消掉）
3. **政策口径核验**——至少逐条对源过一次，参照深圳 P1-5 查出 3 处转述偏差的教训
4. **账号就绪**——城市号（公众号/小红书/抖音）注册完成
5. **系列拓扑定稿**——复用还是重排，写进该城自己的结构规划
6. **脚本派生**——先按规程 3 改 `BASE`，再改文案
7. **开产**

**闸口**：`docs/14-运营管理/B-策划与决策/03-三城分阶段排期表-深圳东莞广州.md` 定的原则是「**不验证不扩**」。本次只建目录，**不触发该闸口**。
