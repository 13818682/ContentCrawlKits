# 发布素材自动化方案

## 文档概述

本文档解决一个问题：**如何把"初稿 MD"自动转化为 9 大平台的"最终发布素材"**（文案变形 + 配图 + 封面 + 元数据 + 视频）。

- **上游输入**：`03-内容创作` 系列初稿 MD（S1/P1-P5，纯文字 + markdown 表格，暂无配图）
- **规范依据**：`08-九大平台文案撰写要求说明书`（各平台文案/配图/规格）、`05-热点日历`（发布时间）
- **工具依据**：`09-工具链使用手册`（MCP 与技能）
- **架构位置**：补齐设计文档中"多模态制作层"的落地细节（原方案只有"图文转视频、数字人口播"的高层概念，未定义"配图怎么自动生成"）

**核心结论**：配图缺口 = 数据图（85%可自动化）+ 封面/信息卡（70%可自动化）+ 视频（50%可自动化）。对深圳中考赛道，配图 90% 是"数据图"而非"美图"，因此自动化程度高于一般内容号，且最值钱的配图恰好最容易自动化。

## 一、问题定义：初稿 MD → 发布素材的缺口

### 1.1 现有状态 vs 目标状态

| 维度 | 现有状态 | 目标状态 |
|------|------|------|
| 文案 | 初稿 MD（公众号定稿版，纯文字+表格） | 9 平台各自适配版（公众号/小红书/抖音/头条…） |
| 视觉 | 无配图、无封面 | 数据图 + 封面/首图 + 信息卡（各平台规格） |
| 元数据 | 无 | 标题 + 标签 + 话题 + 发布时间（按 08 规范） |
| 视频 | 无 | 抖音/快手/B站短视频（数字人/图文成片） |

### 1.2 缺口拆解

以一篇公众号终稿（如 P5-4 分数线复盘）为例，它到"可发布"之间缺的是：

| 缺口 | 举例 | 自动化手段 |
|------|------|------|
| 文案变形 | 公众号长文 → 小红书 400 字 + 抖音 60 秒脚本 | LLM + 08 提示词模板 |
| 数据图 | 分数线对比柱状图、梯队分布图、AC/D 分差图 | Python + matplotlib/echarts |
| 封面/首图 | 公众号封面 900×383、小红书首图 1080×1440 | HTML 模板 → 截图 |
| 信息卡 | 清单体、步骤图、决策树 | HTML 模板 → 截图 / Mermaid |
| 视频 | 数字人口播 + 图文成片 | 剪映 + 腾讯智影 |

## 四、数据图生成方案（最高杠杆，重点展开）

### 4.1 为什么数据图是第一优先级

1. **品牌壁垒**：HSEE 人设是"懂政策的数据控学长"，数据图是竞品最缺、最难抄的资产。
2. **复用性**：一次写好脚本，180 所学校、6 大系列、40+ 篇文章全部复用。
3. **成本极低**：纯本地 Python，无订阅费，运行一次出全系列图。

### 4.2 图表类型 → 数据源映射

| 图表类型 | 数据源（HSEE 视图/表） | 用到的系列 |
|------|------|------|
| 分数线历年对比柱状图 | `v_school_scores_timeline`（score_ac_boarding 等） | P3/P5-4 |
| 梯队分布图 | 分数线分组 | P3-3 |
| AC/D 分差排行图 | `v_school_scores_timeline`（score_ac vs score_d） | P3-2/P3-6-3 |
| 考生人数趋势折线图 | 历年考生数（11.2万→15.3万） | S1/P3-1 |
| 学位供给结构图 | 2026 招生计划（公办/民办/中职） | S1/P5-1 |
| 等级分布图（A+/A/B+…） | 单科等级比例 | P3-1 |
| 3+4/3+2 专业分数线图 | `v_school_enrollment_detail` | P3-5 |

### 4.3 数据图脚本设计要点

| 要点 | 说明 |
|------|------|
| 一套模板多校复用 | 函数化：`plot_school_trend(school_name)` 传校名即出图 |
| 中文字体 | 需配置中文字体（SimHei/Noto Sans SC），否则中文乱码 |
| 品牌配色 | 固定一套配色（数据图统一视觉，呼应"数据控"人设） |
| 输出规格 | 同一数据出多尺寸：正文配图(1200×900) + 小红书首图(1080×1440) |
| 满分归一化 | 跨年份对比必须归一化（见 P5-4 的 610→630 教训） |

## 五、封面/首图/信息卡方案

### 5.1 模板化（推荐，保证品牌统一）

**原理**：把"标题 + 核心数据 + 品牌色"做成 HTML/CSS 模板，用无头浏览器截图。一个选题换文字和数据，30 秒出一套封面。

| 模板类型 | 用途 | 输出规格 |
|------|------|------|
| 封面模板 | 公众号/头条封面 | 900×383、1200×900 |
| 首图模板 | 小红书/抖音首图（带文字标题） | 1080×1440、9:16 |
| 信息卡模板 | 清单/步骤/决策树 | 800×1000 |
| 数据卡片 | "1个数字+1句话"冲击型 | 1200×900 |

### 5.2 与纯 AI 生图的取舍

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| HTML 模板截图 | 品牌统一、可复现、零成本 | 样式有限 | **主打** |
| AI 生图（Flux/即梦/豆包图像） | 场景图、氛围图 | 风格不稳定、需人工挑 | 点缀（学校场景、封面背景） |

> **原则**：封面/首图用模板保证 9 平台视觉一致；AI 生图只做场景点缀，不做主视觉。

## 六、视觉风格统一规范（品牌视觉识别）

### 6.1 为什么必须统一

自动化量产最大的风险是**"风格漂移"**：数据图一个配色、封面另一个风格、信息卡又一套字体——9 个平台看起来像 9 个不同的号，直接损害"懂政策的数据控学长"的专业感和信任度。

统一视觉 = 品牌识别。目标是：用户刷到任何一张图，一眼认出"这是 HSEE"。

### 6.2 品牌色板（设计 token）

色板不是写死在各处，而是**集中在一个 config 文件**里，数据图脚本和封面模板都从它读取——改一处，全系列同步换肤。

| 用途 | 色值（建议） | 说明 |
|------|------|------|
| **主色（品牌蓝）** | `#1F5FA8` | 理性、专业、可信——"数据控"的底色 |
| **强调色（暖橙）** | `#F5A623` | 用于 CTA、关键数字、重点高亮 |
| **涨/跌语义色** | 涨 `#D64541`（红）/ 跌 `#2E9E6B`（绿） | 遵循国内"红涨绿跌"习惯 |
| **文字主色** | `#1A1A1A` | 标题、正文 |
| **文字次级** | `#6B7280` | 说明、注释 |
| **背景** | `#FFFFFF` / `#F8FAFC` | 图卡底、图表底 |

### 6.3 字体系统

| 场景 | 字体 | 说明 |
|------|------|------|
| 数据图 | 思源黑体 / Noto Sans SC | 无衬线，数字清晰，中文无乱码 |
| 封面/首图标题 | 思源黑体 Bold / 阿里巴巴普惠体 | 醒目、有力 |
| 正文文案 | 平台默认 | 文案不强制字体（各平台自渲染） |

### 6.4 图表风格规范（数据图统一）

| 规范项 | 规则 |
|------|------|
| 图表类型 | 趋势用折线、对比用柱状、结构用环形/堆叠——不混用 |
| 坐标轴 | 去掉冗余网格线，保留关键刻度；Y 轴从"有意义的基线"起 |
| 数据标签 | 关键数值直接标注，减少"看图找数" |
| 标题/图例 | 统一位置（标题左上、图例右上） |
| 水印/角标 | 固定右下角（见第七章） |
| 跨年份对比 | 必须归一化满分（见 P5-4 的 610→630 教训） |

### 6.5 封面/信息卡布局规范

| 规范项 | 规则 |
|------|------|
| 布局栅格 | 封面固定"标题区 + 数据区 + 品牌区"三段式 |
| 留白 | 统一边距（如 40px），不塞满 |
| 标题 | 字号/位置统一，与 08 文档的标题公式对齐 |
| 品牌区 | 右下角固定 logo + 水印 |

### 6.6 落地方式

- 一个 `design_tokens` 配置（色板/字体/间距/栅格）统一管理
- 数据图脚本、封面模板都从它读取 → 保证"一张图、一个风格"
- 新增平台/新图类型时复用同一套 token，不重新设计

## 七、内容防盗与版权保护（水印方案）

### 7.1 剽窃风险分析

| 风险 | 说明 |
|------|------|
| **数据图被截走** | 数据图是核心资产——竞品最"爱盗"做好的图，因为它自己不会做 |
| 文案被洗稿 | 公众号/头条/知乎长文被搬运、洗稿 |
| 封面/首图被套用 | 模板化封面易被复制 |

> 数据图是最容易被盗、也最值得保护的——它是 HSEE 的差异化壁垒。

### 7.2 图片水印方案（分层：防得住且不毁观感）

| 水印类型 | 位置 | 透明度 | 说明 |
|------|------|:---:|------|
| **角标 logo** | 右下角 | 100% | 品牌标识，小尺寸，不遮挡内容 |
| **半透明斜纹水印** | 斜铺整图 | 6-10% | "HSEE"字样，防直接截走，不影响阅读 |
| **数据来源水印** | 图底部 | 常规 | "数据来源：HSEE · 深圳教育局"——声明 + 防盗 |

**关键原则**：水印的透明度是核心——太淡没防护，太浓毁观感。**角标 logo（清晰）+ 半透明斜纹（防截）+ 数据来源（声明）三层组合**，兼顾美观与防护。

### 7.3 文案防盗

| 方式 | 说明 |
|------|------|
| 平台原创声明 | 公众号"原创"标记、头条号"原创"认证（平台自动全网比对） |
| 数据署名 | 每张图、每处数据都标"HSEE"——洗稿也洗不掉数据出处 |
| 文末版权声明 | 固定模板："本文数据来自 HSEE，转载请联系" |

### 7.4 技术防盗（后期可选）

| 手段 | 说明 | 成本 |
|------|------|:---:|
| 平台原创保护 | 公众号/头条自带 | 0 |
| 全网版权监测 | 维权骑士/快版权/易撰，发现盗用自动通知 | ¥几十-几百/月 |
| 隐形数字水印 | 不影响视觉，可溯源（技术较复杂） | 后期 |

### 7.5 各平台水印差异

| 平台 | 平台自带水印 | 需自加 |
|------|------|------|
| 公众号 / 头条 / 知乎 | 无 | 图片加水印 |
| 小红书 | 有（自动加） | 可再加角标 |
| 抖音 / 快手 | 有（自动加） | 无需额外 |

### 7.6 落地顺序（成本从低到高）

1. **第 1 步就做**：数据图脚本内置"角标 logo + 数据来源水印 + 半透明斜纹"（开发成本≈0，从源头防）
2. 封面/信息卡模板预留水印位
3. 发布时启用平台原创保护
4. 验证期后视被盗情况，再上第三方监测

## 十、自动化流水线设计（半自动 + 人审）

```
初稿 MD（公众号定稿）
      │
      ├─① 文案变形 ──→ LLM 按 9 平台提示词 → 9 平台文案
      ├─② 数据图生成 ──→ Python 读数据库 → 数据图（多尺寸，自动加水印）
      ├─③ 封面生成 ──→ HTML 模板 + 数据图 → 封面/首图/信息卡（自动加水印）
      │
      ▼
   【人工终审】（合规红线：04 清单 + 数据准确性 + 品牌调性）
      │
      ▼
   蚁小二排期发布 → 数据回传 → 反馈迭代
```

### 关键设计原则

| 原则 | 说明 |
|------|------|
| **半自动，不追求全自动** | 教育内容是强监管赛道，最后一步必须人审（合规 + 数据准确性） |
| **人审只审"关键点"** | 数据对不对、红线踩没踩、标题党没有——不逐字润色 |
| **机器管"量产"** | 批量、规格、尺寸、格式适配由脚本负责 |

## 十一、风险与边界

| 风险 | 说明 | 应对 |
|------|------|------|
| 平台 API 限制 | 小红书/抖音对自动发布/营销内容审核严 | 发布用蚁小二官方通道，避免灰色接口 |
| 数据准确性 | 数据图出自数据库，错误会被放大 | 脚本加数据校验 + 人审核对来源 |

| AI 生图合规 | AI 生成内容需标识（见 04 清单） | 按 04 规范标注"AI 生成" |
| 满分/计分变化 | 跨年份数据对比需归一化 | 数据图脚本内置归一化逻辑 |
