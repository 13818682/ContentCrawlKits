### 0.1 三种采集工具的核心差异

验证阶段涉及内容采集，市面上有三种主流工具可以选择。它们不是同类产品——各自主攻完全不同的场景，能力交集很小。

| 工具 | 一句话定位 | 核心能力 |
|------|-----------|---------|

### 0.3 关键差异深入分析

#### anysearch-skill的两个独特优势

**优势1：能搜微信公众号完整原文和评论**

anysearch-skill可以检索微信公众号的完整原文与评论。原生Agent搜索工具普遍无法收录公众号内容（公众号是封闭生态，内容不在公网搜索引擎索引中）。对于深圳中考内容创作，这意味着你可以直接搜索公众号上的竞品深度长文——这是MediaCrawler做不到的（微信封闭生态，任何第三方工具都无法稳定抓取公众号）。

对于公众号内容的做法：每天人工浏览对标公众号的最新推送（微信里直接看），发现值得参考的文章后用anysearch-skill搜索标题或extract链接拿到全文。

**优势2：垂直专业领域检索能力**

对于中考政策解读类内容，anysearch-skill可以直接检索：
- **学术场景**：IEEE、知网等最新教育政策研究论文，拿到精准的政策分析方法论
- **政企公告**：各级教育局的官方文件原文，而非媒体的二次解读摘要
- **法律条文**：教育相关法规的结构化原文

普通搜索引擎搜"深圳中考指标生政策"只能搜到新闻媒体的解释性文章，anysearch可以深入到原始政策文件和学术分析。这对产出"官方政策原文解读"类选题——家长最信任的内容类型——非常有价值。

#### MediaCrawler的不可替代性

自媒体平台（小红书/抖音/B站）的内容存在于APP和移动端H5中，通过加密API动态加载。firecrawl和anysearch-skill作为网页级工具，根本访问不到这些内容。MediaCrawler通过复用本地Chrome浏览器登录态（CDP远程调试），绕过各平台加密签名，无需逆向工程。开源免费（Apache 2.0协议），15k+ GitHub Stars，社区活跃。

**唯一短板**：不支持微信公众号抓取（微信是封闭生态，任何第三方工具都难以稳定抓取）。公众号内容由anysearch-skill补足。

#### firecrawl的精准场景

- 需要JS渲染的页面（某些学校官网用React/Vue构建）
- 大范围crawl一个站点的所有页面（如深圳招考网的全部公告）
- 需要截屏存档的页面

#### MediaCrawler与anysearch-skill的操作衔接

MediaCrawler覆盖小红书/抖音/B站/知乎/微博/快手6个平台，**唯独不支持微信公众号**（微信是封闭生态，任何第三方工具都无法稳定抓取）。因此需要anysearch-skill补足公众号这一块。

**MediaCrawler负责"采集"**：
- 小红书/抖音/B站/知乎/微博/快手 → 完整文案+互动数据+作者信息，CSV导出
- 三种模式：关键词搜索批量抓取 / 对标博主主页全量抓取 / 单条精准抓取
- 部署在自己电脑上，数据完全私有

**anysearch-skill负责"公众号补全"**：
- 公众号内容MediaCrawler拿不到 → 用anysearch-skill搜索+清洗
- 搜索关键词或标题 → 拿到公众号文章全文Markdown + 评论区
- 或者已知文章链接 → 用 `extract` 清洗全文

**实际操作流（每天10分钟）**：
```
1. MediaCrawler定时任务（凌晨2点自动跑）→ 早上查看CSV导出结果
2. 小红书/抖音/B站/知乎内容 → MediaCrawler已拿到全文，直接看
3. 公众号内容 → MediaCrawler拿不到，需要额外操作：
   a. 人工浏览对标公众号今日更新（用微信看）→ 发现值得参考的文章
   b. anysearch-skill search "文章标题 site:mp.weixin.qq.com" → 拿到全文
   c. 或者复制文章链接 → anysearch extract 清洗为Markdown
4. 政策原文用anysearch直接搜教育局官网 → 拿到原始文件
```

**关于anysearch-skill的能力边界**：
- ❌ **不能**自动读取某个公众号的全部历史文章列表
- ❌ **不能**主动监控某公众号的新文章更新（公众号更新需要人工在微信里浏览发现）
- ✅ **能**按关键词搜索公众号文章并返回全文
- ✅ **能**清洗单篇已知链接的公众号文章为Markdown

**关于图片OCR**：
- MediaCrawler、anysearch-skill和firecrawl的原生OCR能力都有限
- 如果竞品以图片表格形式呈现数据（如"2025深圳各校分数线一览"截图），这些工具都拿不到表格里的数据
- **但这对你影响很小**——因为你不依赖竞品的数据，你的数据来源是HSEE数据表。竞品图片中的"四大名校三年分数对比"，你提取的是"对比多年分数线"这个选题角度，具体数字从你自己的数据库填充

## 第一章：为什么必须先验证

### 1.1 两个待验证的核心假设

自建平台一次性投入¥65,000-135,000，月度运营¥13,000-15,000。在这个投入之前，有两个假设必须用真实数据验证：

| 假设 | 如果错了意味着什么 | 验证方法 |
|------|-------------------|---------|
| **假设A**：外部平台（小红书/抖音/B站）的内容能有效吸引深圳家长关注并互动 | 内容矩阵全部白做，所有时间金钱投入归零 | 发布内容→追踪各平台互动数据→对比同赛道竞品均值 |
| **假设B**：被内容吸引的家长愿意扫码进入HSEE小程序并完成注册 | 流量无法转化为产品用户，内容矩阵只赚吆喝不赚钱 | 每条内容配置独立追踪参数→HSEE后台统计扫码→注册转化 |

### 1.2 验证成本 vs 失败成本

```
验证阶段总投入：¥2,500-3,000（2个月工具费）
自建MVP投入：  ¥65,000-135,000

如果直接自建，假设失败了 → 损失 ¥65,000+
如果先验证，假设失败了 → 损失 ¥3,000，且积累了200+条内容的经验
```

**风险降低倍数：40倍以上。**

### 2.2 每个工具的配置步骤

#### 2.2.1 MediaCrawler（自媒体竞品采集）— 第一天完成

**部署步骤**（约30-40分钟）：

1. 克隆开源仓库：
   ```bash
   git clone https://github.com/NanmiCoder/MediaCrawler.git
   cd MediaCrawler
   ```
2. 安装依赖：
   ```bash
   uv sync                              # 推荐UV方案（依赖零冲突）
   uv run playwright install chrome     # 安装Chrome浏览器驱动
   ```
3. 配置Chrome远程调试（降低风控核心步骤）：
   ```bash
   chrome.exe --remote-debugging-port=9222   # Windows
   ```
   在弹出的Chrome浏览器中手动登录小红书、抖音、B站等账号（以后爬虫自动复用登录态）
4. **配置关键词库**：编辑 `config/base_config.py`，修改 `KEYWORDS` 列表：
   ```
   深圳中考志愿填报 | 深圳指标生政策 | 深圳中考一分一段表
   深圳公办高中录取分数线 | 深圳中考冲稳保 | 深圳中考滑档
   深圳中考补录 | 深圳中考复读 | 深圳中职择校
   深圳中考自主招生 | 深圳中考报名流程 | 深圳中考计分规则
   ```
5. 配置对标博主ID列表（在 `config/base_config.py` 中设置 `CRAWLER_CREATOR_ID_LIST`）：
   - 在小红书搜索"深圳中考"，筛选粉丝量前10的博主，记录其主页ID
   - 在抖音重复同样操作，添加5-10个对标账号
   - 在B站添加3-5个深圳中考相关的UP主
6. **设置采集参数**（修改 `config/base_config.py`）：
   ```python
   CRAWLER_TYPE = "search"          # 关键词搜索模式
   KEYWORDS = ["深圳中考志愿填报","深圳指标生","深圳中考一分一段表",...]
   SLEEP_TIME = 12                  # 抓取间隔≥12秒/条
   DATA_SAVE_TYPE = "csv"           # CSV导出（可改为mysql）
   ```
7. **设置定时任务**：每天凌晨2:00自动执行
   ```bash
   # Windows 任务计划程序 或 Linux cron:
   0 2 * * * cd /path/to/MediaCrawler && uv run main.py --platform=xhs --lt=qrcode --type=search
   ```
8. **每天早上**：查看 `data/` 目录下导出的CSV文件

## 第三章：账号矩阵搭建

### 3.1 平台选择：先做4个平台

验证阶段集中精力在转化路径最短的平台。**视频号和头条暂不做**。

| 平台 | 优先级 | 账号数量 | 理由 |
|------|--------|---------|------|
| **小红书** | ⭐⭐⭐ 最高 | 2-3个号 | 深圳家长（尤其妈妈）搜索"中考"的第一入口。图文笔记适合政策科普，评论区互动转化好 |
| **抖音** | ⭐⭐⭐ 最高 | 2-3个号 | 流量最大，算法对新号友好。短视频适合"3分钟讲清楚一个政策" |
| **公众号** | ⭐⭐ 中 | 1个号 | 深度长文主阵地，可嵌入HSEE小程序卡片直接跳转 |
| **B站** | ⭐ 低 | 1个号 | 适合长视频教程（10分钟完整填报教学），但流量红利不如小红书/抖音。先做一个号试水 |
| **视频号** | ❌ 暂不做 | 0 | 需要真人出镜或企业认证，验证阶段门槛偏高 |
| **头条** | ❌ 暂不做 | 0 | 泛流量多、精准家长少，转化率预计最低。验证阶段ROI不足以覆盖运营成本 |

### 3.3 账号注册与养号注意事项

| 注意事项 | 具体操作 |
|---------|---------|
| **一机一卡一号** | 每个平台账号用不同手机号注册。推荐和多号或阿里小号（月费¥5/号）。同一手机号注册多个账号会被平台标记 |
| **养号期** | 注册后不要立刻发内容。先正常浏览同行内容3-5天：每天刷30分钟+给同行内容点赞评论。让平台算法认为这是一个"正常用户" |
| **不要互关** | 多个号之间不要互相点赞、互相关注、互相评论。平台能识别出同一个人的多个账号之间的互动是营销行为 |
| **头像和简介** | 每个号用不同的真人风格头像（可以用AI生成），写不同的个人简介。不要用默认头像或直接写公司名 |
| **小程序码嵌入策略** | 小红书：在个人简介放"深圳中考资料获取"引导语+图片（含小程序码）<br>抖音：在个人简介放引导语（"想获取你的志愿方案？点这里"）<br>公众号：文章中直接嵌入HSEE小程序卡片<br>B站：视频简介区放链接+口播中引导"详情见评论区" |

### 4.1B 学校介绍专题（独立内容线）

学校介绍是家长决策链条上最关键的内容类型之一。家长在了解政策后，下一个问题一定是"那我的孩子能上什么学校？这些学校怎么样？"——学校介绍就是回答这个问题的内容。

#### 已有资产

你在 `E:\1.HSEE\1.HSEE-Prj\4.数据导入模板\学校介绍MD文档\` 目录下拥有学校介绍MD文件，按以下结构组织：

```
学校介绍MD文档/
├── 普高/
│   ├── 完整详细版/    ← 每所学校约8000字深度报告
│   └── 简版速览版/    ← 每所学校约2000字家长速览版
└── 中职技工/
    ├── 完整详细版/
    └── 简版速览版/
```

每所学校的文档结构和内容深度已在 `深圳普通高中完整介绍框架（2026.06.19）.md` 中定义。这些MD文件由LLM基于官方数据生成、经人工校验，数据准确度远高于任何网络采集的内容。

#### 学校介绍在内容矩阵中的角色

学校介绍不是孤立内容——它与其他内容类型形成互补：

| 内容类型 | 回答家长的问题 | 学校介绍与之配合 |
|---------|--------------|----------------|
| 政策科普 | "中考怎么考？" | 政策中提到某类学校时，链接到对应学校介绍 |
| 志愿填报攻略 | "志愿怎么填？" | 推荐学校时直接引用学校介绍中的数据 |
| 案例故事 | "别人家怎么选的？" | 案例中涉及的学校，附上学校介绍链接 |
| **学校介绍** | **"这所学校怎么样？"** | **独立成篇，也可以拆解嵌入其他内容** |

#### 学校介绍的内容质量标准

每篇学校介绍（无论是完整版还是速览版）必须覆盖以下核心信息：

| 信息类别 | 具体内容 | 数据来源 |
|---------|---------|---------|
| **基础信息** | 学校名称、类型（公办/民办）、所在区域、创办时间、占地面积 | HSEE `schools` 表 |
| **招生分数** | 近3年AC类/D类录取分数线（含住宿/走读区分） | HSEE `admission_scores` 表 |
| **招生计划** | 当年招生人数、AC类/D类分配、自主招生名额 | HSEE `enrollment_plans` 表 |
| **教学特点** | 师资力量、特色课程、社团活动、教学理念 | 已有MD文件 |
| **高考成绩** | 高优率/本科率（如有公开数据）、知名校友/升学去向 | 已有MD文件 |
| **校园生活** | 宿舍条件、食堂、校风、校园环境 | 已有MD文件 |
| **分班情况** | 是否有分班考、重点班/平行班设置 | 已有MD文件 |
| **指标生** | 各初中分配到该校的名额数 | HSEE `quota_allocations` 表 |

**合规底线**（学校介绍特有问题）：
- 高考成绩数据必须注明来源（"据学校官方公布"或"据家长反馈"），不得编造
- 如果某校高考成绩未公开（如新建学校无高考出口），明确标注"暂无高考成绩数据"
- 不对学校进行排名性质的比较（如"XX学校比XX学校好"），只做客观信息呈现
- 不得引用未经证实的内部数据或小道消息

### 4.2 每日工作流（总时长3-4小时）

#### 第一步：采集+选题（每天30分钟）

```
08:00-08:05  打开MediaCrawler的data目录 → 查看凌晨自动采集导出的CSV文件
08:05-08:15  人工扫一遍CSV（按互动量排序后的Top20）
             → 在飞书"素材入库表"中标记3-5个可用的选题方向
             → 判断标准：互动量高（>同类均值）+ 你能写出差异化
08:15-08:25  对每个候选选题，从HSEE数据表查询相关官方数据：
             → 选题涉及某学校的 → 查 admission_scores + schools
             → 选题涉及指标生 → 查 quota_allocations
             → 选题涉及招生 → 查 enrollment_plans
             → 把查到的数据粘贴到"选题排期表"中该选题的备注列
08:25-08:30  用 anysearch-skill 搜索选题相关的政策原文和公众号深度分析
             → search "深圳中考 [选题关键词] 政策 2026 site:szeb.sz.gov.cn"
             → 拿到官方政策原文 + 竞品公众号分析
             → 提取关键段落粘贴到选题备注中
```

#### 第二步：改写创作（每天90分钟，产出5-8篇）

这是最核心的环节。**不要搬运，不要简单同义词替换**。每一篇都要做到：结构重构 + 数据替换 + 观点注入。

**改写五步法（单篇15-20分钟）**：

```
① 读（3分钟）
   通读竞品原文+你采集的官方数据+政策原文
   理解：这篇的核心观点是什么？它的结构是怎样的？
   标记：哪些信息点是"客观事实"（可以引用），哪些是"主观观点"（需要你用自己的话来写）

② 拆（2分钟）
   拆出3-4个核心信息点
   对每个信息点做判断：
   - 如果是政策事实 → 用你从anysearch搜到的官方原文替换
   - 如果是数据引用 → 用你从HSEE数据表查到的官方数据替换
   - 如果是个人观点 → 删掉，用自己的差异化观点替代

③ 注（3分钟）
   注入差异化：
   - 补充竞品没提到的角度（竞品写"怎么做"，你写"为什么这么做"+"常见错误"）
   - 补充HSEE数据表里独有的数据（竞品没有的数据）
   - 补充本地化的细节（学校真名、真实分数线、真实区域特征）
   - 换一个组织结构（竞品是list体，你改成问答体或故事体）

④ 写（8分钟）
   用豆包/Kimi辅助生成初稿：
   粘贴改写指令（见4.3节Prompt模板）→ 粘贴官方数据 → 粘贴竞品结构
   → 生成 → 检查：数据对不对？语气对不对？有没有编造的内容？

⑤ 改（3分钟）
   人工润色，重点关注：
   - 删掉AI套话（"值得注意的是""综上所述""在当今社会""随着…的发展"）
   - 加上真实的深圳地点名、学校名、区域名
   - 调整语气匹配你的人设（专业人士不卖萌，过来人不说教）
   - 检查数据是否和HSEE数据表一致（这一步抽查即可，不用每篇校对）
```

**关于"数据替换"的具体操作示例**：

假设竞品素材写的是：

> "2025年深圳中学的录取分数线大概是575分左右，位于全市前列。"

你的HSEE数据表显示：`admission_scores` → 深圳中学, 2025, AC类住宿生, 574分

你改写后变成：

> "根据深圳市招考办公布的数据，深圳中学2025年AC类住宿生录取线为574分。这个分数在全市公办高中中排名第一，比第二名深圳实验学校高中部高出2分。"

差别在于：竞品写的是"大概""左右"——不可靠感。你写的是精确数字+数据来源+对比分析——权威感。

**关于为什么用飞书而不是本地Excel**：

|------|:---:|:---:|

## 第六章：数据追踪与判断指标

### 6.1 一级硬指标（必须全部达标才Go）

| 指标 | 目标值 | 为什么是这个数 | 计算公式 |
|------|--------|---------------|---------|
| **篇均扫码率** | ≥ 2% | 如果100人看了内容只有不到2人扫码，说明要么内容对家长没吸引力，要么转化路径设计有问题。2%是内容→小程序转化的行业参考下限 | HSEE后台"外部平台来源"扫码数 ÷ 对应平台内容总阅读/播放量 |
| **单用户获客成本** | ≤ ¥30 | 对比微信朋友圈广告获客成本¥50-80，内容获客的优势就是低成本。¥30是验证期可接受的上限（vs 工具月费¥400÷目标月增注册数） | 月度工具总支出 ÷ 月度外部平台新增注册用户数 |
| **零侵权投诉** | 8周0投诉 | 验证期出现侵权投诉说明"深度改写"流程有漏洞，需要先补齐再考虑规模化 | — |

### 6.2 二级观察指标（不硬性达标但影响怎么做）

| 指标 | 观察什么 | 怎么用 |
|------|---------|--------|
| **各平台扫码率对比** | 小红书 vs 抖音 vs 公众号 vs B站，哪个转化率最高 | 自建阶段优先对接转化率最高的平台 |
| **各主题扫码率对比** | A类(政策) vs B类(填报) vs C类(录取)，哪类内容扫码率最高 | 决定自建阶段的内容品类配比 |
| **各内容形式扫码率** | 短图文(400-700字) vs 深度长文(1200-2000字) vs 口播视频 vs 长视频教程 | 决定自建阶段的内容形式配比 |
| **各账号人设表现** | "专业人士"vs"过来人家长"vs"避坑指南"哪种人设最受欢迎 | 自建阶段复制成功人设，放弃失败人设 |
| **"官方数据版"vs"竞品数据版"表现** | 用HSEE官方数据的内容和用竞品数据的内容，互动和转化有差异吗 | 如果官方数据版显著更好→自建阶段坚决走"数据驱动"路线 |
| **发布时间效果** | 不同时间段发布的内容互动量差异 | 自建阶段预设最优发布时间 |
| **标题类型效果** | 数字型 vs 痛点型 vs 疑问型 | 沉淀为标题模板库 |
| **最优引流位置** | 小程序码在文首/文末/评论区/简介区，哪个扫码率最高 | 固化内容模板中的指引位置 |

### 6.3 数据记录机制

**每条内容的完整追踪链**：

```
发布内容（含HSEE追踪参数）
    │
    ▼
蚁小二回传各平台数据（曝光量/阅读量/互动量）
    │
    ▼
HSEE后台统计追踪参数 → 扫码数 → 注册数
    │
    ▼
飞书"数据复盘表"汇总（每条内容发布48h后填写）
```

**HSEE追踪参数命名规范**：

```
?from={平台}_{账号}_{内容编号}_{日期}

示例：
?from=xhs_szplan_001_20240801     （小红书·深学规划·第1篇·8月1日）
?from=dy_bikeng_015_20240815      （抖音·避坑指南·第15篇·8月15日）
?from=gh_szplan_003_20240809      （公众号·深圳中考志愿规划·第3篇·8月9日）
?from=bilicollege_002_20240810    （B站·深圳中考升学通·第2篇·8月10日）
```

## 第七章：Go/No-Go决策框架

验证期结束后，按以下框架做决策。**不要凭感觉**，每个判断都要有数据支撑。

### 🟢 Go（启动自建MVP）

**必须同时满足以下全部条件**：

- [ ] 篇均扫码率 ≥ 2%
- [ ] 单用户获客成本 ≤ ¥30
- [ ] 8周内零搬运侵权投诉
- [ ] 至少识别出2个"高转化选题方向"（扫码率 ≥ 3%的二级标签）
- [ ] 至少1个平台的内容生产→发布→追踪全SOP已跑通（能稳定日产5篇且质量可接受）

**Go之后做什么**：
- 立即启动自建MVP建设（详见完整建设方案第八章）
- 验证期积累的200+条内容、7个养好的号、跑通的SOP全部转化为自建平台的冷启动资产
- 第9-12周（自建MVP建设期间）：继续用商用工具维持内容产出（量可以降到每天3篇保住账号活跃度）
- 自建平台就绪后一次性切换

### 🟡 Conditional Go（调整后继续验证）

**出现以下情况之一**：

**情况1：篇均扫码率在1%-2%之间**

→ **先优化转化路径，再继续验证4周**
- 检查清单：
  - HSEE落地页是否让人困惑？（用户扫码后看到什么？是不是预期不符？）
  - 小程序码/链接位置是否太隐蔽？
  - 引导话术是否不够吸引？（"了解更多" vs "获取你的专属志愿方案"——后者转化率可能高3倍）
  - 各平台的小程序码是否清晰可扫？（有些平台会压缩图片）
- 优化后再跑4周，目标仍然是≥2%

**情况2：单用户获客成本在¥30-50之间**

→ **用更多内容量摊薄固定成本**
- 把日产内容量从5篇提到8-10篇，看边际获客成本能不能降到¥30以内
- 如果日均8-10篇仍不能，说明内容获客效率不足以支撑这个赛道，考虑No-Go

### 🔴 No-Go（停止，重新审视）

**出现以下任一情况**：

- [ ] 篇均扫码率 < 1%（持续4周以上且无明显改善趋势）
- [ ] 单用户获客成本 > ¥50
- [ ] 收到平台侵权投诉（说明"深度改写"流程有根本性漏洞）
- [ ] 8周累计产出200+条内容，但没有一条扫码率超过2%

**No-Go之后做什么**：
- 不是"这个项目不行"，而是"这个假设在当前条件下不成立"
- 先做根本原因分析：
  - 是内容质量不够好？→ 对比你的内容和竞品高互动内容，差距在哪
  - 是选题方向全错了？→ 深圳家长到底在搜什么？用anysearch重新调研
  - 是HSEE产品本身对用户没有吸引力？→ 优化HSEE落地页和注册流程
  - 是账号权重不够？→ 养号时间不够 or 内容量不够 or 互动率太低
- 根据根因决定下一步：调整后重新验证 or 转向其他获客渠道

## 第八章：验证通过后的衔接

### 8.1 验证期积累资产的复用

你跑完8周后积累的资产不会浪费：

| 资产 | 数量 | 如何复用到自建阶段 |
|------|------|-------------------|
| 已发布内容 | 200-300条 | 作为自建平台的冷启动素材，导入数据库作为"风格参考" |
| 养好的平台账号 | 5-7个 | 继续使用，直接对接蚁小二API批量管理 |
| 飞书数据复盘表 | 200-300条数据记录 | 导出为自建平台的种子训练数据——"哪些选题好、哪些风格好"的量化依据 |
| 跑通的SOP | 完整的选题→改写→发布→追踪流程 | 翻译成代码逻辑：采集规则、Prompt模板参数、发布时间策略 |
| 已验证的高转化内容公式 | "XX选题+XX人设+XX标题风格=XX%扫码率" | 自建平台优先自动化生产这类内容 |
| HSEE追踪参数体系 | 已验证的追踪链路 | 自建平台继承同一套追踪规范，数据连续性不中断 |

### 8.2 过渡期方案（第9-12周）

自建MVP建设大约需要4周。这4周里——**不要停更**：

```
继续用商用工具维持内容产出
├── 产量降至每天3篇（保住账号活跃度和权重即可）
├── 开发人员同时搭建自建平台
├── 每周保留1-2篇高质量内容（保持追踪数据的连续性）
└── 自建平台就绪 → 一次性切换 → 商用工具退订
```
