# 自媒体内容自动化创作平台 — 建设方案与可行性评估

## 一、先厘清：你到底要建一个什么东西

在开始架构设计之前，先把这个平台的本质说清楚。

### 1.1 这个平台解决什么问题

你手上有HSEE小程序（深圳中考志愿填报咨询服务），它的商业模式是：**免费内容获客 → 注册 → 付费订阅方案**。这个模式要跑通，有两个瓶颈：

1. **内容从哪里来**：HSEE需要持续产出高质量深圳中考内容（政策科普、案例故事、学校报告、Q&A），如果全靠人工写，产能跟不上。
2. **用户从哪里来**：微信小程序是私域，自己不会长腿跑出去拉人。需要外部公域平台（抖音/小红书/B站/头条）持续引流。

这个内容自动化平台，就是同时解决这两个瓶颈的工厂：

```
                    ┌──→ 内容供血 → HSEE小程序（留住用户、推动付费）
内容自动化平台 ────┤
                    └──→ 外部矩阵 → 抖音/小红书/B站/头条/公众号（拉新获客）
                                         │
                                         └──→ 内容中嵌入小程序码 → 用户扫码进入HSEE
```

### 1.2 这个平台不是什么

- **不是通用AI写作工具**：它不做"输入主题→输出文章"的简单生成。它的核心差异在于有深圳中考专属知识库（历年分数线、学校数据、政策规则），生成的内容自带本地化数据，不是通用套话。
- **不是纯爬虫工具**：采集只是入口，核心价值在后续的"分析→去重→重组→生成"流水线。
- **不是HSEE的替代品**：它是HSEE的上游供应商，两个项目是上下游关系。

## 二、我设计的架构：七层流水线

### 2.1 整体逻辑

```
层1：采集        →  从8个平台抓取深圳中考相关内容
层2：清洗分析    →  去重、筛优质素材、自动打标签
层3：选题管理    →  基于素材分析，发现内容缺口，生成选题建议
层4：AI生成      →  用RAG+Prompt批量生成原创内容
层5：多模态制作  →  图文转视频、数字人口播、格式适配
层6：分发        →  一键发布到6个外部平台 + 同步到HSEE小程序
层7：反馈        →  收集各平台数据，回流优化选题和生成策略
```

### 2.2 每层怎么做（我的独立判断）

#### 层1：采集层

**我的判断**：不需要从头造轮子。MediaCrawler是GitHub上成熟的开源方案（15k+ stars），覆盖小红书/抖音/B站/知乎/微博/快手/视频号7个平台。它的核心优势是复用Chrome浏览器登录态，不需要逆向工程各平台的加密算法——这对小团队来说是决定性的。

**具体做法**：
- 核心采集用MediaCrawler（开源免费），关键词池配置深圳中考相关词条
- 官方数据（教育局公告、招生计划）用轻量定制爬虫（requests+BeautifulSoup足够），不需要重量级框架
- 备用采集通道：如果某平台反爬升级导致MediaCrawler失效，临时切换anysearch-skill搜索+firecrawl抓取作为补采方案
- 采集频率：每天凌晨2点定时跑一次，间隔≥12秒/条，不激进

**我的判断vs方案文档的差异**：
- 我不建议一开始就用新榜热点API（另一笔月费¥99/月）。MVP阶段手动监控教育局官网就够了，热点响应机制可以等V1.1再做
- 采集内容时效性限制在近3个月，超出这范围的历史内容对选题参考价值不大

#### 层2：清洗分析层

**我的判断**：这一层是平台的"质检车间"，决定了后面AI生成的内容质量。核心做三件事：去重、筛选、打标签。

**具体做法**：
- **第一轮去重（表层）**：URL完全相同→直接删除；标题完全相同→只保留互动量最高的
- **第二轮去重（语义层）**：用中文文本向量模型（我推荐用text2vec-large-chinese而非tao-8k，前者在中文语义相似度任务上表现更好且社区更活跃），将文案转成向量，余弦相似度>0.75判定为同质内容，只保留互动量最高的1篇
- **自动打标签**：采用规则优先+模型兜底的策略。80%的内容靠关键词匹配就能准确分类（比如文案里出现"指标生""名额分配"→标签B04），剩下20%边界case交给LLM判断
- **质量筛选**：点赞+收藏<10的低互动内容直接标记为低质，不进入选题库

**我为什么不用K-Means聚类**：设计文档里提到用K-Means自动分组。我的判断是——对于深圳中考这个垂直领域，标签体系已经很明确了（23个业务主题），不需要无监督聚类去"发现"新类别。用规则匹配直接分类，效率和准确率都更高。

#### 层3：选题管理层

**我的判断**：这是整个平台最被低估的一层。好的选题管理直接决定了内容质量的上限。

**具体做法**：
- **内容缺口分析**：对比竞品已覆盖的主题和你的标签体系，标记出"竞品写了但你没写"和"谁都没写的蓝海主题"
- **选题优先级算法**：每个选题给一个综合分 = 时效性(30%) + 竞品热度(25%) + 内容缺口(25%) + 用户需求信号(20%)
  - 时效性：当前时间离这个主题的最佳发布时间越近，分越高
  - 竞品热度：竞品同类内容的互动量越高，分越高
  - 内容缺口：这个主题竞品覆盖率越低，分越高
  - 用户需求信号：HSEE后台用户搜索/提问频率越高，分越高
- **选题排期**：按优先级排序，匹配平台发布日历（公众号周二/五，小红书午间+晚间等）

#### 层4：AI生成层

**我的判断**：这一层是核心，但不是调个API就完事了。真正的难点在于：内容要准确（深圳中考数据不能错）、要原创（不能搬运竞品）、要有效（家长看完想注册）。

**我的设计分三步**：

**第一步：RAG检索增强**——生成前先检索
- 搭建深圳中考专属知识库（向量化存储），包含：
  - 2023-2026各校录取分数线（AC类/D类）
  - 公办高中梯队信息（四大/八大/二十大学校详情）
  - 指标生分配规则+各区名额数据
  - 中考政策原文（2026最新版）
  - 志愿批次设置和投档规则
- 生成某个选题时，先检索Top-3最相关的知识片段注入Prompt

**第二步：Prompt分层设计**
- 不搞一套统一Prompt，而是三层结构：
  - **基础层**（所有平台共用）：身份设定+知识约束+合规底线
  - **平台层**（按平台定制）：小红书要emoji+短句、公众号要长文+专业、抖音要口语+节奏
  - **选题层**（按具体选题注入）：当前选题的知识片段、参考结构、目标受众
- 每一层可以独立修改调优，不用动整个Prompt

**第三步：生成后校验**
- 自动校验：生成的学校名称/分数线/招生人数是否在数据库中真实存在（防止LLM幻觉）
- 相似度检测：与源素材的语义相似度必须<30%
- 合规标识注入：按《人工智能生成合成内容标识办法》在文末添加标识

**LLM选型判断**：
- 主力用豆包（字节跳动，对中文内容理解最好，且对自媒体文案风格适配度高）
- 备用智谱GLM-4（避免单点依赖）
- 两个都是国产模型，数据不出境，合规
- 按量计费，日产50条内容大概日均API费用¥60-120

#### 层5：多模态制作层

**我的判断**：视频是流量增量，但不要追求全自动。我的策略是"图文为主力、视频为辅助"。

**具体做法**：
- **图文**：Markdown编写→BFF解析为结构化块→小程序原生渲染（这个流程HSEE已经有了，复用）
- **短视频**：AI生成的抖音口播脚本→剪映AI图文成片自动匹配素材→人工检查字幕和关键帧（10分钟/条）
- **数字人视频**：公众号长文→提炼3分钟脚本→腾讯智影数字人口播→自动字幕（几乎全自动）
- **信息图表**：分数线数据→ECharts模板渲染→导出PNG（全自动）

**我的判断vs方案文档的差异**：
- 不追求一开始就做全品类视频。MVP阶段只做抖音口播脚本（纯文字产出），视频制作留到V1.1
- 剪映AI和腾讯智影的API不一定稳定，先手动使用验证效果，稳定后再做API对接

#### 层6：分发层

**我的判断**：分发的关键是"一次生产、多平台适配"，不是"一次生产、原样复制"。

**具体做法**：
- **内容变形链**：一篇公众号深度长文(1500字)→拆成3篇小红书图文(500字/篇)→提取1条抖音口播(3分钟脚本)→扩展为1个B站教学(8分钟脚本)
- **分发工具**：蚁小二专业版（¥129/月），支持6个平台统一管理+定时发布+数据回传
- **发布时间策略**：
  - 小红书：12:30 / 20:00（午休+下班后）
  - 抖音：19:00-21:00（晚高峰）
  - 公众号：周二/周五 12:00（固定推送养成用户预期）
  - B站：12:00 / 19:00

**与HSEE的对接**（最关键的一环）：
- 本平台产出的内容，通过API同步到HSEE数据库
- 同步的内容元数据包括：内容ID、标题、正文、内容类型、城市、权限等级、简版/完整版、标签、来源、版本号
- HSEE端接收到后在小程序内展示，用户看到的是"小程序原生内容"，不知道背后是自动化平台生产的

#### 层7：反馈层

**我的判断**：反馈闭环是让平台越跑越聪明的关键，但MVP阶段不需要做太重。

**具体做法（分阶段）**：
- **MVP**：只做基础的发布状态追踪（发了没有、哪个平台、发布时间、发布链接）
- **V1.1**：各平台数据回传（播放量、点赞、收藏、评论、分享），每日自动汇总到选题看板
- **V1.2**：HSEE数据回传（用户在小程序内的阅读行为、注册转化、付费转化），根据转化数据反向优化内容策略
- **V2.0**：自动调权——高转化内容类型自动增加生产权重，低转化类型减少

## 三、技术选型：我的判断

### 3.1 不走弯路的选型原则

1. **能用开源就用开源**：采集(MediaCrawler)、向量库(Milvus)、缓存(Redis)、数据库(MySQL)全部开源
2. **国产优先**：LLM用豆包/智谱（数据不出境、中文效果好）
3. **Python全家桶**：采集、后端、NLP都用Python，一个人能搞定全栈
4. **渐进式复杂度**：MVP不引入Kubernetes、不引入微服务，一个Docker Compose就跑起来

### 3.2 核心技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 爬虫 | MediaCrawler (Python+Playwright) | 开源成熟方案，CDP复用登录态免逆向 |
| 后端 | FastAPI | 异步高性能，自带API文档 |
| 数据库 | MySQL 8.0 | 够用、稳定、运维成本低 |
| 向量库 | Milvus Lite | 嵌入式部署，768维检索毫秒级 |
| 队列 | Redis + Celery | 采集/生成/分发任务异步化 |
| 文件 | MinIO | 兼容S3，存图片/视频/导出文件 |
| LLM | 豆包(主) + 智谱(备) | 中文能力强，按量计费 |
| NLP | text2vec-large-chinese | 中文语义相似度SOTA，社区活跃 |
| 前端 | Vue 3 + Element Plus | 管理后台，与HSEE技术栈一致 |
| 部署 | Docker Compose | 单机一键部署，MVP不引入K8s |

### 3.3 为什么我不推荐某些方案文档里的选择

| 方案文档推荐 | 我的判断 | 理由 |
|------------|---------|------|
| tao-8k向量模型 | text2vec-large-chinese | 后者在MTEB中文榜单上表现更好，社区更活跃，文档更全 |
| K-Means聚类自动分组 | 规则匹配+LLM兜底 | 垂直领域标签体系明确，不需要无监督聚类 |
| 部署tao-8k本地模型 | 云服务器CPU即可运行 | text2vec推理不需要GPU，8核CPU就够了 |
| 新榜热点API（¥99/月） | MVP阶段手动监控 | 教育局官网有RSS，新榜API可以V1.1再上 |

## 六、可行性评估

### 6.1 技术可行性：✅ 没有硬障碍

- 每一项技术都有成熟的开源方案，不需要从零研发
- 最大的技术风险是平台反爬升级，但MediaCrawler社区活跃（15k+ stars），通常能快速跟进
- LLM幻觉是工程问题不是技术障碍：通过"数据库校验+人工审核"双保险解决

### 6.2 业务可行性：✅ 逻辑成立但需数据验证

- HSEE主平台的商业模式已经跑通（小程序+LLM方案+付费订阅）
- 内容平台的定位是"降本增效"：降低内容生产成本、增加获客渠道
- 关键的待验证假设：**外部平台内容能否有效转化为HSEE注册用户**
  - 如果每条内容带来10个阅读→1个扫码→月300条内容→300个新用户→按HSEE 5%付费转化率→15个付费用户
  - 15人 × ¥500客单价 = ¥7,500月增营收，不足以覆盖平台成本
  - 但如果有30个账号矩阵同时跑：15人×30账号 = ¥225,000月增营收，就完全成立
  - **结论**：模型成立的前提是矩阵规模，MVP先用5-10个号验证转化率

### 6.3 经济可行性：⚠️ 有条件的可行

- 月度成本¥13,000-15,000，对于一个小型内容团队来说不算高
- 如果用商用工具路线先验证（¥626/月），验证成本极低
- 核心经济账：HSEE客单价¥199-¥2,999，内容平台的盈亏平衡点是每月多带来30-60个付费用户
- 2026年深圳中考15.3万考生、家长群体约45万人，这个转化目标完全在合理范围内

### 6.4 核心风险

| 风险 | 等级 | 应对 |
|------|------|------|
| 外部内容转化率低于预期 | 🔴 最高 | 先用商用工具+5个小号低成本验证1-2个月，数据不好就不自建 |
| 平台反爬升级封号 | 🟡 中 | 多账号轮换、备用商用工具、IP代理池 |
| AI内容被平台限流 | 🟡 中 | 70%AI+30%人工润色、合规标识、低相似度 |
| LLM API成本超预期 | 🟢 低 | 按量计费可控、用量监控告警、缓存重复Prompt |
| 政策变动致知识库过期 | 🟡 中 | 月度更新、教育局RSS监控 |

## 七、验证阶段：低成本试跑实施细则（第1-8周）

### 7.1 为什么必须先验证

自建平台一次性投入¥65,000-135,000，月度运营¥13,000-15,000。在这个投入之前，有两个假设必须先验证：

| 假设 | 如果错了意味着什么 |
|------|-------------------|
| 外部平台（抖音/小红书/B站）的内容能有效吸引深圳家长关注 | 内容矩阵全部白做 |

这两个假设不需要写一行代码就能验证。用现成的商用工具+人工操作跑1-2个月，总成本不超过¥1,500，就能拿到数据做决策。

### 7.3 账号矩阵搭建

#### 7.3.1 平台选择：先做4个平台，不做6个

验证阶段集中火力在转化路径最短的平台，不要分散精力：

| 平台 | 优先级 | 账号数量 | 理由 |
|------|--------|---------|------|
| **小红书** | ⭐⭐⭐ 最高 | 2-3个号 | 深圳家长（尤其妈妈）搜索"中考"的第一选择，图文内容适合政策科普，评论区互动转化好 |
| **抖音** | ⭐⭐⭐ 最高 | 2-3个号 | 流量最大，短视频适合做"3分钟讲清楚XX政策"，信息流推荐机制对新手友好 |
| **公众号** | ⭐⭐ 中 | 1个号 | 长文深度内容的主阵地，直接嵌入小程序卡片引导跳转HSEE |
| **B站** | ⭐ 低 | 1个号 | 适合长视频教学（10分钟完整填报教程），但流量红利不如小红书/抖音，先做一个号试水 |
| **视频号** | ❌ 暂不做 | 0 | 需要真人出镜或认证，验证阶段门槛偏高 |
| **头条** | ❌ 暂不做 | 0 | 泛流量多、精准家长少，转化率预计最低 |

#### 7.3.2 账号人设定位

不要所有号用一个名字，要设计差异化人设覆盖不同类型的家长：

| 账号 | 平台 | 人设 | 内容风格 | 目标家长 |
|------|------|------|---------|---------|
| 深学规划 | 小红书 | 深圳本地升学规划师，5年经验 | 专业干货+数据表格，语气温和可靠 | AC类高知家长（南山/福田） |
| 深圳中考那些事 | 小红书 | 过来人家长身份，"我家孩子2025年刚考完" | 情感共鸣+经验分享+避坑提醒 | D类焦虑妈妈（龙岗/宝安） |
| 深学规划 | 抖音 | 同上，视频版 | 3分钟口播："一个视频讲清楚指标生" | 泛家长 |
| 深圳中考避坑指南 | 抖音 | 接地气风格，"每年都有家长踩这个坑" | 痛点开头+案例+解决方案 | 零基础家长 |

#### 7.3.3 账号注册注意事项

- **一机一卡一号**：每个平台账号用不同手机号注册（推荐和多号或阿里小号，月费¥5/号）
- **养号期**：注册后先正常浏览同行内容3-5天（每天刷30分钟+点赞评论），不要立刻发内容
- **不要互关**：多个号之间不要互相关注，平台会识别为营销矩阵
- **小程序码嵌入**：公众号文章底部放HSEE小程序卡片；小红书/抖音在简介或个人主页放小程序码图片；B站在视频简介区放链接
- **头像和简介**：每个号的头像、昵称、简介要像真人，不要用默认头像或公司名

### 7.4 内容生产流水线（SOP）

这是验证阶段最重要的部分。下面的流程一个人每天花3-4小时就能跑通。

#### 7.4.1 第一步：选题（每天30分钟）

**早上的工作**：
1. 打开MediaCrawler的data目录，查看凌晨自动采集导出的CSV文件
2. 导入优采云，自动去重后按互动量排序
3. 从Top20中手动挑选5-8个选题（标准：互动量高+你能写得出差异化+适合改编成你的风格）
4. 检查你的选题排期表（飞书），确保不重复、各主题均衡覆盖

**选题的三级标签体系**（直接复制进优采云的自定义标签）：

```
一级标签（时间周期）：
A-前期政策(3-5月)  B-中期填报(6-7月)  C-后期录取(7-8月)

二级标签（业务主题，共20个核心）：
A01-基础政策解读    A02-计分规则        A03-指标生政策
A04-自主招生        A05-公办民办区别    A06-报名流程
B01-一分一段表      B02-志愿批次规则    B03-冲稳保梯度
B04-指标生使用技巧  B05-滑档退档避坑    B06-公办高中梯队
B07-民办高中筛选    B08-填报系统操作    C01-录取分数线
C02-滑档补救        C03-补录流程        C04-中职择校
C05-复读政策        C06-高一衔接规划

三级标签（内容形式）：
tip-避坑干货  case-真实案例  qa-问答  table-数据表格
policy-政策解读  template-模板方案
```

#### 7.4.2 第二步：改写创作（每天90分钟，产出5-8篇）

这是核心环节。**不要直接搬运**，每一篇都要做深度改写：

**改写SOP（单篇15-20分钟）**：

1. **读**（3分钟）：通读竞品原文，理解它的核心观点和结构
2. **拆**（2分钟）：拆出3-4个核心信息点，标注哪些可以复用（政策事实）、哪些需要重写（个人观点）
3. **注**（3分钟）：注入你的差异化——
   - 补充竞品没提到的深圳本地数据（去教育局官网找）
   - 换个角度（竞品写"怎么做"，你写"为什么这么做"+常见错误）
   - 换个结构（竞品是list体，你改成问答体或故事体）
4. **写**（8分钟）：用豆包/Kimi辅助生成初稿——
   - 粘贴你的改写指令（见下方Prompt模板）
   - 检查生成结果：数据对不对？语气对不对？有没有编造的内容？
5. **改**（3分钟）：人工润色——
   - 改掉AI的套话（"值得注意的是""综上所述""在当今社会"）
   - 加上深圳本地的细节（学校真名、真实分数线、真实区域名）
   - 调整语气匹配你的人设

**改写Prompt模板**（直接复制使用）：

```
你是深圳中考志愿填报领域的资深内容编辑。请基于以下参考素材，
创作一篇全新的原创内容。

【硬性要求】
- 字数：400-700字（小红书）/ 800-1200字（公众号）/ 300字口播脚本（抖音）
- 风格：口语化，像家长之间聊天，不要教科书语气
- 结构：开头抛出一个家长真实痛点→3-4个干货要点→结尾给出可操作建议
- 必须嵌入深圳本地数据（如果参考素材里没有，用你知道的真实数据补充）
- 禁止使用的词：值得注意的是、综上所述、在当今社会、随着…的发展
- 禁止搬运原文，全文结构和表述要完全重构

【参考素材】
{粘贴竞品内容}

【平台要求】
目标平台：{小红书/抖音/公众号/B站}
账号人设：{你的账号人设描述}
额外要求：{特定平台的格式要求}

现在开始创作：
```

#### 7.4.3 第三步：发布（每天30分钟）

**发布前检查清单**：
- [ ] 检查所有数据（学校名称、分数线、招生人数）是否正确
- [ ] 标题是否吸引人？（数字+痛点+解决方案，如"深圳中考冲稳保怎么填？3步搞定，附真实案例"）
- [ ] 文末是否有引导？（"你家中考准备得怎么样了？评论区聊聊"）
- [ ] HSEE小程序码/链接是否已嵌入？
- [ ] 与竞品的相似度是否足够低？（至少做到你自己读不出"这是抄那篇的"）

**各平台发布时间**（在蚁小二里预设好，提前一天排期）：

```
小红书：12:30 和 20:00（两个流量高峰，每个号各发1篇）
抖音：19:00-21:00（晚高峰，每天发1条）
公众号：周二和周五 12:00（固定节奏，每周2篇）
B站：周六 12:00（周末流量，每周1篇）
```

> 验证阶段优先级：小红书 > 抖音 > 公众号 > B站。时间和精力优先分配给小红书和抖音。

#### 7.4.4 第四步：数据记录（每天15分钟，收尾工作）

在飞书多维表格的"数据复盘表"中，记录每条内容发布24小时后的数据：

| 字段 | 说明 |
|------|------|
| 发布日期 | 自动 |
| 内容标题 | — |
| 发布平台 | 小红书/抖音/公众号/B站 |
| 三级标签 | 如 B03-tip |
| 曝光量 | 平台后台查看 |
| 阅读/播放量 | — |
| 点赞数 | — |
| 收藏数 | — |
| 评论数 | — |
| 分享数 | — |
| HSEE扫码数 | **最重要的指标**——用HSEE后台的进站来源统计，或用蚁小二+自定义短链接追踪 |

> **关键数据追踪**：给每条发布到外部平台的内容配置不同的HSEE小程序路径参数（如 `?from=xhs_account1_20240801`），在HSEE后台就能精确统计每个账号、每条内容带来了多少注册用户。

### 7.6 数据追踪：判断指标与目标值

验证阶段的核心不是"内容火了没有"，而是"内容能不能带人来"。

#### 7.6.1 一级指标（必须达标，否则不Go）

| 指标 | 目标值 | 为什么是这个数 | 怎么算 |
|------|--------|---------------|--------|
| **篇均扫码率** | ≥2% | 如果100个人看了内容只有不到2个人扫码，说明内容对家长没有吸引力或者转化路径有问题 | HSEE后台"外部平台来源"新注册数 ÷ 外部平台内容总阅读/播放量 |
| **单用户获客成本** | ≤¥30 | 工具月费¥550 ÷ 目标月增注册数。¥30是底线（对比朋友圈广告获客¥50-80），越低于¥30越值得自建 | 月工具费 ÷ 月新增注册用户数 |
| **内容原创度** | 100%无搬运投诉 | 验证阶段就收到侵权投诉=立即停掉，证明这个模式合规风险太高 | — |

#### 7.6.2 二级指标（观察指标，决定怎么做）

| 指标 | 观察什么 | 怎么用 |
|------|---------|--------|
| 各平台篇均互动率 | 哪个平台的内容最能引发家长互动 | 互动率最高的平台，自建阶段优先对接 |
| 各主题扫码率 | 哪种选题的内容扫码率最高 | 自建阶段重点生产这类选题 |
| 各内容形式扫码率 | 短图文/深度长文/口播视频，哪种转化最好 | 决定自建阶段的内容形式配比 |
| 各人设账号表现 | 哪个账号人设最受欢迎 | 自建阶段复制这个成功人设 |
| 发布时间效果 | 哪个时间段发布的内容互动最高 | 自建阶段预设发布时间 |

#### 7.6.3 数据记录模板

在飞书"数据复盘表"中，每条内容发布48小时后填写：

```
内容ID | 发布日期 | 平台 | 账号 | 三级标签 | 内容形式 | 
标题 | 阅读量 | 点赞 | 收藏 | 评论 | 分享 |
HSEE扫码数 | 扫码率(扫码/阅读) | HSEE注册数 | 注册率(注册/扫码) |
发布时间段 | 标题类型 | 备注
```

### 7.7 Go/No-Go决策框架

验证期结束后，按下面的框架做决策，**不要凭感觉**：

#### 🟢 Go（启动自建MVP）— 满足以下全部条件

- [ ] 篇均扫码率 ≥ 2%
- [ ] 单用户获客成本 ≤ ¥30
- [ ] 8周内零搬运侵权投诉
- [ ] 至少识别出2个"高转化选题方向"（扫码率≥3%的主题）
- [ ] 至少1个平台的内容生产SOP已跑通（能稳定日产5篇且质量可接受）

#### 🟡 Conditional Go（调整后继续验证）— 满足以下情况之一

- 篇均扫码率1%-2%之间：**先优化转化路径再继续验证**
  - 检查：HSEE落地页是否让人困惑？小程序码位置是否太隐蔽？引导话术是否不够吸引？
  - 优化后再跑4周
- 单用户获客成本¥30-50之间：**用更多内容摊薄固定成本**
  - 把日产内容量从5篇提到8-10篇，看边际成本能不能降下来
  - 再跑4周

#### 🔴 No-Go（停止，重新审视）— 出现以下任一情况

- 篇均扫码率 < 1%（持续4周以上）
- 单用户获客成本 > ¥50
- 收到平台侵权投诉
- 8周累计产出了200+条内容但没有一条扫码率超过2%
- **根本原因分析**：是内容质量不够好？还是选题方向全错了？还是HSEE产品本身没有吸引力？先搞清楚再决定下一步。

### 7.8 验证通过后的衔接

如果你决定Go，验证期间积累的资产不要浪费：

| 资产 | 如何复用 |
|------|---------|
| 200+条已发布内容 | 自建平台后作为冷启动素材导入数据库 |
| 飞书数据复盘表 | 直接导出为自建平台的种子训练数据（哪些选题好、哪些风格好） |
| 5-7个已养好的平台账号 | 自建平台后继续使用，直接对接蚁小二API批量管理 |
| 跑通的选题→改写→发布SOP | 翻译成代码逻辑：采集规则、Prompt模板、发布时间策略 |
| 已验证的高转化内容模式 | 自建平台后优先自动化生产这类内容 |

**衔接期的过渡方案**（第9-12周，即自建MVP建设期间）：
- 继续用商用工具维持内容产出（不要停，停了账号会掉权重）
- 产量可以降低到每天3篇（保住账号活跃度即可）
- 开发人员同时搭建自建平台
- 自建平台就绪后一次性切换
